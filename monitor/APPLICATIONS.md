# アプリを開く

サイドバーの「アプリ」から、Macのアプリをアイコンで選んで開けます。名前で検索でき、起動中のアプリには印が付きます。すでに起動している同じ場所のアプリは手前に表示します。

- 自動探索: `/Applications`、`~/Applications`、`/System/Applications`、`/System/Library/CoreServices/Applications`。ユーティリティ等のサブフォルダも探索します。
- 一覧にないアプリ: 「アプリを追加」から.appを選択します。選択した場所はこのMacのAIBOU設定に保存します。シンボリックリンクは選択した参照を保持し、更新時にリンク先を再取得します。
- インストール・移動・削除の反映: 「一覧を更新」を押します。
- 同名の別インストール: 別のアイコンとして残します。ポインタを置くか右クリックすると場所を確認できます。「Finderで表示」も使えます。

アプリ内部の補助プログラム、非表示項目、常駐専用アプリは自動一覧から除外します。通常のフォルダのシンボリックリンクはたどりません。探索は20,000項目・深さ8階層までで、読取エラーや上限到達は画面に表示します。全ディスク上の全アプリを網羅する一覧ではありません。

起動にはmacOSの[NSWorkspace.openApplication](https://developer.apple.com/documentation/appkit/nsworkspace/openapplication(at:configuration:completionhandler:))を使います。アプリ名をシェルコマンドに展開しません。macOS側で確認が必要な場合は、通常のシステム確認が表示されます。削除・権限・起動エラーはAIBOU内にも表示します。

これはユーザーが直接クリックして開く機能です。Codexの相談機能からの自動起動や、アプリ一覧のOpenAIへの送信には接続していません。

## アプリの詳細

アイコンを2本指クリック（右クリック）して「詳細」を選ぶと、使用状況を確認できます。

- **CPU・メモリ**: 選んだインストール先の本体・内包ヘルパーと子プロセスの値を合算します。CPUは1コアを100%とする尺度です。メモリはフットプリントと常駐量を別々に表示します。
- **ネットワーク**: 詳細を開いている間、約3秒ごとにnettopの1秒区間の送受信量・速度を更新します。プロセス集計行だけを加算し、接続行との二重計上を避けます。PIDだけでなく計測前後の起動日時も照合します。起動以来の累積量ではありません。
- **ディスク**: アプリ本体、標準保存先に見つかった関連候補、本体と関連候補を合わせた論理サイズを表示します。開いた時に集計し、「容量を再集計」で更新します。場所別の容量と判定根拠も確認できます。

「合算したプロセスと帰属の根拠」を開くと対象のPID・実行パスを確認できます。同じBundle IDでも別の場所にあるアプリは混ぜません。外部の子プロセスは親子関係による推定です。別のGUIアプリや共用OSサービスまで一律には加算しません。短命なプロセス、読取権限がないプロセス、親子関係が失われた外部ヘルパーは取得・帰属できない場合があります。取得できた範囲と欠測・推定・過去値を区別します。

関連候補はBundle IDとアプリ名からApplication Support、Caches、Preferences、Containers、WebKit等の標準保存先を探します。独自の保存先、共有グループ領域、ユーザーが任意の場所に保存した書類まで網羅するものではありません。関連候補がそのアプリだけの専有データであるとも断定しません。

容量集計はハードリンク・重複するルートを二重計上せず、シンボリックリンクをたどりません。25万項目・15秒・128エラーを上限とし、途中で止まった場合は読取範囲の容量を表示します。論理サイズはAPFSの圧縮・クローン等を反映した実占有量や、削除時に空く容量とは異なります。ファイルの変更・削除機能はありません。
