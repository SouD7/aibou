# AIBOU ハードウェア診断カタログ

## 状態チェックの画面

症状（ユーザーから見える不具合）と原因候補（内部の状態・仮説）を分けて管理します。

| タブ | 一覧に表示するもの |
| --- | --- |
| すべて | 症状カード。症状を手動で選択し、「詳細」から原因候補を開く。 |
| 今の候補 | 原因候補の有効なチェックが1つ以上ある症状。症状自体の選択は条件にしない。 |
| 選択した症状 | 「この症状がある」に手動チェックを付けた症状。 |
| 自動判定 | モニタの観測でチェックを付け外しできる原因候補8種類。 |
| 手動判定 | 観測だけではチェックできない原因候補。症状カードではなく原因候補を表示する。 |

原因の自動チェックは「観測条件に該当」の場合だけオンにします。継続確認中、欠測、古い値、監視停止中を正常・異常と断定しません。自動対応の原因を手動で変更すると、そのオン・オフを保持し、「自動に戻す」で再び観測に追従します。症状の選択、原因候補、確認作業の記録は独立です。リセットは手動指定を消し、自動判定はその時点の結果を再適用します。状態はアプリ起動中のみ保持します。

既存カタログの観測条件と原因仮説を分離しています。例えば「OSの熱負荷上昇」は自動対応、「吸排気口の閉塞」や「冷却系の故障」は手動確認です。熱状態だけからこれらの故障を自動チェックしません。CPU・熱・swapなどの同じ観測条件を複数の関連症状に紐付け、詳細と原因一覧は同じチェック状態を参照します。

以下の表は元の70ケースの調査カタログです。表のIDと自動判定エンジンは維持しますが、この表の項目を症状カードへ変換することはしません。症状は`Sources/DiagnosticSelection.swift`に独立した一覧として定義し、関連する複数の原因候補を紐付けます。「CPU高負荷」「swap使用」「空き容量不足」等は原因側にだけ表示し、「操作が遅い」「保存できない」等を症状側に表示します。

原因タブでは、関連する症状名・症状の例からも原因候補を検索できます。同名の手動原因は「確認の対象」の副題で区別します。確認作業のチェックは同じ確認対象の原因カードで共有し、原因の選択そのものとは独立です。

## 判断の範囲

このカタログは、AIBOUの観測値と利用者の症状から「確認候補」を提示するためのものです。ハードウェア故障を確定するものではありません。表示は観測事実、ハードウェア原因の仮説、ソフトウェア・設定・周辺機器など別の可能性、安全な対処、追加確認を分けます。Apple公式資料は確認・対処手順の根拠であり、個別部品の故障を証明するものではありません。部品レベルの仮説はAIBOUによる切り分け候補です。自動修復、アプリの強制終了、設定変更、ファイル削除は行いません。

自動チェックのしきい値はAIBOUの運用上のヒューリスティックであり、Appleの故障判定値ではありません。CPU全体90%以上または同一コア95%以上は20秒継続（計測間隔が6秒を超えると連続性をリセット）、ストレージは空き10 GiB未満または総容量の10%未満を注意候補にします。温度の数値、バッテリー80%、充放電1000回などを全Mac共通の故障基準にはしません。

現在取得できる情報は、OSの熱状態（正常／やや高い／高い／重大）、CPU全体とコア別使用率、swap使用量、バッテリー残量・充電中・外部電源、起動データ領域の空き容量と総容量です。内部温度、ファン回転数、満充電容量は対応機種で条件付き収集しますが、本チェックの自動判定には使用しません。メモリプレッシャー、SMART、バッテリー状態・サイクル数・設計容量、Wi-FiのRSSI/SNR/リンク速度、GPU使用率、FPS、クラッシュ／パニックログは取得しません。

表の「自動」は現在の監視値で条件を評価します。「手動」は症状とAppleのツールを使って確認します。自動の該当表示も原因確定ではなく、手動確認へ進むためのチェックです。
