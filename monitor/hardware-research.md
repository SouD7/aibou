# macOS ハードウェア起因を疑う症状の診断カタログ（公式根拠）

調査日: 2026-09-13。Apple Support / macOS ユーザガイドを一次情報として使用する。

## 判定モデル

監視アプリの各チェックは、次の三層を必ず分ける。

1. **観測値** — アプリが取得した事実（CPU 使用率、メモリプレッシャー、I/O、電源状態、接続状態、イベント履歴）。
2. **原因仮説** — 観測値と症状の組合せから「疑い」として示す。単一の数値だけでハードウェア故障と断定しない。
3. **手動確認／対処** — Apple の診断、設定、ケーブル交換、周辺機器の切り分け、修理依頼など、利用者が確認できる次の行動。

各項目の状態は `該当`、`未該当`、`判定不能`（未対応機種、権限なし、センサー未公開、データ不足）とする。温度、ファン回転数、バッテリー容量、充放電回数、外部ディスプレイ上限は**機種・構成・使用状況依存**であり、全 Mac 共通の固定しきい値にしない。

## チェック項目（監視値 → 仮説 → 手動確認／対処）

| # | 分類 | 観測値（チェック可能な事実） | 原因仮説としての表示 | 手動確認／対処 |
|---:|---|---|---|---|
| 1 | 熱・ファン | CPU/GPU 高負荷と、対応機種でのファン高速回転・温度上昇が同時に持続 | 高演算負荷または高い周囲温度／通気不良により冷却が必要 | 固く平らで通気の良い面に移し、通気口を塞がない。CPU 上位プロセスを確認。 |
| 2 | 熱保護 | `kernel_task` の CPU 使用率が高く、ファンも活発 | 温度管理のため macOS が他プロセスの CPU 使用を抑制している可能性。`kernel_task` を原因プロセス扱いしない | 温度低下後に収束するか確認し、持続時は負荷・通気を点検。 |
| 3 | 温度センサー | サードパーティー由来の温度値のみ、または外装が熱いという申告のみ | 監視値は補助的な兆候で、ハードウェア故障の診断根拠には不足 | Apple は第三者温度アプリだけに依存して故障診断しないよう案内。異常な発熱は修理相談へ。 |
| 4 | CPU 飽和 | CPU の User/System/Idle、上位プロセス、経時履歴 | 持続的に Idle が少なく特定プロセスが上位なら、その処理が応答遅延・発熱の有力因子 | アクティビティモニタでプロセスを特定し、不要な処理を終了／設定変更。 |
| 5 | GPU 飽和 | GPU 履歴の高い棒が連続し、発熱・電池消耗と同時 | グラフィックス処理が性能低下、発熱、電池消耗に寄与している可能性 | GPU 履歴と対象アプリを確認。対応機種・用途では Apple は外部 GPU による負荷分散を案内。 |
| 6 | メモリ逼迫 | メモリプレッシャーが黄／赤、スワップ使用量・圧縮量、上位メモリプロセス | RAM 不足または特定アプリのメモリ消費により遅延が出ている可能性 | 黄は将来不足の可能性、赤はより多くの RAM が必要という Apple の表示。不要アプリを閉じ、機種が対応すれば増設可否を確認。 |
| 7 | メモリ表示の誤判定防止 | 「空きメモリが少ない」だけ | 単独では異常と判定しない | Apple は空き／未使用メモリがあっても性能向上とは限らないと説明。プレッシャーとスワップを優先して表示。 |
| 8 | ストレージ容量 | 起動ボリュームの空き容量、空き容量の急減、書込み失敗 | 空き容量不足がスワップや更新、ファイル書込みを阻害している可能性 | 使用量の大きいデータを確認し、バックアップ後に安全に空きを確保。固定の「危険 %」は設定しない。 |
| 9 | ストレージ I/O | 読書きバイト数・回数、特定プロセスの I/O、I/O 高止まりと応答遅延 | インデックス、同期、スワップ、または異常なディスク待ちが寄与している可能性 | アクティビティモニタの「ディスク」でプロセスを確認。I/O 量だけで物理故障とは断定しない。 |
| 10 | ディスク健全性 | Disk Utility の (a) S.M.A.R.T. 致命的ハードウェアエラー、(b) First Aid 失敗／修復不能 | (a) は物理ディスク故障の強い根拠。(b) はファイルシステム／ディレクトリ構造の修復失敗を示すが、単独では物理故障の証明ではない | いずれも可能な限りバックアップ。(a) は修理／交換を検討。(b) は復旧環境で対象階層を順に確認し、修復不能時は再インストールまたは修理相談。First Aid は全ての問題を検出・修復するものではない。 |
| 11 | バッテリー状態 | システム設定の「正常」または「修理サービス推奨」、充電量、電源、エネルギー消費上位 | 「修理サービス推奨」は新品時より充電可能量が低下。急速な消耗はアプリ負荷・設定・電池劣化のいずれもあり得る | 状態を最優先に表示し、使用履歴（24 時間／10 日）とエネルギー上位アプリを確認。 |
| 12 | バッテリー回数・最適化 | 充放電回数、機種モデル、満充電に達しない充電履歴 | 回数だけでは劣化・故障を断定できない。最適化充電が 80 %超の充電を保留することがある | Apple のモデル別最大回数と照合し、バッテリー状態も確認。全機種共通の回数しきい値は使わない。 |
| 13 | 給電・電力 | AC／バッテリーの現在電源、充電中か、接続アクセサリ、電池残量の経時変化 | 電源アダプタ／ケーブル／ドックの給電不足、または高負荷による電池消耗の可能性 | Apple 認定アダプタを使用し、アクセサリを外して再現性を確認。充電できることとデータ接続を許可したことは別。 |
| 14 | Wi-Fi／ネットワーク | 送受信バイト、パケット、スループット、接続先・接続状態の変化 | トラフィック量は利用状況であり、回線品質・ISP・ルーター・電波干渉の故障断定根拠ではない | Wi-Fi 勧告とワイヤレス診断を実行。別ネットワークでの再現性、ルーター／ISP を確認。 |
| 15 | Bluetooth／無線入力 | Bluetooth のオン状態、ペアリング／再接続状態、機器の電池残量（取得可能時） | 接続解除、電池切れ、圏外／干渉、または周辺機器側の可能性 | 機器の電源・充電・検出可能状態を確認し、解除後に再接続。USB 接続で切り分ける。 |
| 16 | USB／Thunderbolt | 接続・切断イベント、認識の有無、「USB デバイスが無効」などの通知 | 給電不足、ハブ／ケーブル／ポート、または接続許可が原因の可能性 | 直接別ポートへ接続し、セルフパワー型ハブは AC 接続。Apple シリコン搭載ノートではアクセサリ許可も確認。 |
| 17 | 外部ディスプレイ／ドック | 接続表示、解像度、表示の消失、ドック接続時だけの再現 | ディスプレイ／ケーブル／アダプタ／ポート互換性またはモデル上限の可能性 | 「ディスプレイを検出」、電源、正しいケーブル・アダプタ、機種の対応台数を確認。 |
| 18 | スリープ／復帰 | スリープ解除回数、予期しないスリープ／覚醒、CPU を使うバックグラウンド処理 | 共有サービス、バックグラウンド処理、周辺機器、設定が関与する可能性 | 共有サービスと CPU プロセスを確認し、再起動して再現を確認。 |
| 19 | 予期しない再起動／カーネルパニック | 再起動・シャットダウン・パニックログの反復、外部機器接続との時系列 | ソフトウェアが最も可能性が高いが、外部装置、ハードウェア損傷、互換性問題も候補 | 外部機器を外し、一台ずつ再接続して再現を確認。セーフモードと Apple Diagnostics を使う。 |
| 20 | カメラ | カメラがアプリに現れない、カメラ横の緑ランプ点滅（ユーザー申告） | 権限／スクリーンタイム／アプリの問題を先に除外。緑ランプ点滅や継続不動作は修理が必要な場合がある | macOS 更新、カメラ権限、スクリーンタイム、再起動を確認。 |
| 21 | オーディオ | 選択中の入力／出力装置、音量／消音、接続中の USB・Thunderbolt・HDMI 音声機器 | 出力先の誤選択、外部機器へのルーティング、外部機器／ケーブルの可能性 | 外部音声機器を外し、内蔵スピーカーと音量・消音・出力先を確認。内蔵がなお不動作なら修理候補。 |
| 22 | 物理損傷・安全 | 落下、画面割れ、液体接触、膨張・異臭・異常発熱などのユーザー申告 | 監視値で安全性を否定できない。液体・破損・内蔵バッテリーの損傷は高優先度の物理リスク | 損傷品を使用せず、自己修理せずに修理窓口へ。液体損傷は現行のノートに LCI がある場合がある。 |
| 23 | ハードウェア診断 | Apple Diagnostics のリファレンスコードと実行日時 | 内蔵ロジックボード、メモリ、無線などの問題を特定する補助根拠 | 外付け USB や他社製 PCI、アプリ／拡張機能の競合は診断対象外。陰性結果を「問題なし」と表示せず、対象外を明示。macOS Tahoe 26 以降は個別診断を選べる。 |

## 表示上の安全策

- 「温度が高い → CPU 故障」「高 CPU → 熱暴走」「S.M.A.R.T. 正常 → ストレージ問題なし」のような単因子断定を避ける。メトリクスは `観測`、根拠のある組合せだけを `疑い`、Apple Diagnostics／First Aid／周辺機器の切り分けを `要確認` と表示する。
- 監視できないもの（内部温度、センサー健全性、液体侵入、ケーブル品質、Wi-Fi 電波環境、外部機器の互換性）は「判定不能」。推定値の単位・取得元・時刻を必ず表示する。
- 危険を伴う表示は、煙、異臭、膨張、液体接触、割れ、通電時の異常発熱を「使用中止・修理相談」とする。アプリ上で分解、バッテリー交換、通気口への異物挿入を案内しない。

## バージョン・適用範囲の注意

- Apple の案内は機種と macOS 版で異なる。特に Apple Diagnostics は macOS Tahoe 26 以降で個別診断の選択肢があり、アクセサリ許可の挙動は Apple シリコン搭載ノートに適用される。
- Apple の公式バッテリー回数表はモデル別であり、本文の「容量・寿命は使用状況、構成、充電方法で異なる」という注意を維持する。
- 温度・S.M.A.R.T.・電池の原始値をアプリが取得できても、Apple はそれを単独で故障診断する基準を公開していない。そのため製品 UI では「警告」よりも「確認を勧める根拠」として扱う。
