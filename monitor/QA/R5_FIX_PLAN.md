# R5修正計画

1. READMEとAPIコメントで、CPU継続判定にはMonitorStoreの監視セッションを利用すること、単発snapshotは継続性を証明しないことを明記する。既存のrunning/snapshotの安全契約は維持する。
2. 機器一覧cacheから実取得日時を伝播し、TTLをContinuousClockで管理する。注入時計でTTL前後・壁時計の前進/後退・取得失敗を検証する。
3. 保存索引復元で完了日時、件数、rootとsummaryの合計、error件数を検証する。不正データは保存ファイルを変更せず拒否する。正常な欠損/部分取得と旧版の任意フィールド省略を保持する。
4. 先に回帰fixtureを追加して現行での失敗を確認し、修正後に全テスト・build・署名/lint・独立コード/設計レビューを実施する。

スリープqueue競合・大規模JSON・診断全量投影等の未再現/未測定WATCHは今回の確定3指摘とは分け、残る制約として報告する。新規依存・永続化schema変更・GUI再起動・ユーザー保存ファイル操作は行わない。
