# AIBOU Monitor

AIBOUのバックエンド検証用macOSアプリです。PCの状態をキャラクターで表現する前段として、収集できる情報、値の意味、権限や機種による欠損を11個のタブと「状態チェック」で確認できます。

## 症状と原因候補のチェック

サイドバーの「状態チェック」に、10分類・70ケースの症状、原因候補、対処法、確認済みチェック、Apple公式資料を追加しました。[全ケース一覧](DIAGNOSTICS.md) と [調査根拠](hardware-research.md) を参照してください。

8ケースは観測値で自動評価します。OSの熱負荷上昇、CPU全体高負荷、同一コア高負荷、スワップ使用、バッテリー残量低下・重大低下、外部電源中の非充電、起動データ領域の空き容量低下です。残り62ケースは手動確認です。症状・原因・対処法の検索、分類、自動／手動／今の候補の絞り込みができます。

自動結果は「観測条件に該当」「継続確認中」「今回の条件に該当せず」「情報不足」で表示します。基本監視停止中、再開前の古い区間、10秒を超える古い値、未取得や部分取得は現在の異常・正常の根拠にしません。CPUのしきい値は全体90%・同一コア95%を20秒以上、空き容量は10 GiB未満または10%未満というAIBOUの注意目安で、Appleの故障基準ではありません。

スワップ使用は現在のメモリ不足を、非充電は電池故障を、OSの熱状態はCPU固有の温度や実際のクロック抑制量を確定しません。症状や確認済みチェックは起動中だけ保持し、タブを切り替えても残ります。手動チェックは確認作業の記録であり、原因の確度を自動で上げません。修復や削除、設定変更は自動実行しません。

将来のアバター側では `MonitorStore.diagnosticResults(now:)` からID・状態・判定根拠・取得元・時刻を持つCodable結果を参照できます。単独利用では `DiagnosticEngine.ingest(_:now:)` に新しいObservationSnapshotを順番に渡し、`evaluate(_:now:)` で結果を取得します。連続性はメモリ内の少数の記録で管理し、プロセス履歴は追加保存しません。

ビルドの下限はmacOS 13で、実機検証はApple M1のMacBook Air / macOS 26.6.2で行っています。すべてのMac・macOS版で同じ値が取得できることは保証していません。取得できない値は0で埋めず、「権限不足」「非対応」「取得失敗」「計測待ち」などの状態と理由を表示します。

## ビルドと実行

Xcode Command Line ToolsまたはXcodeが必要です。ターミナルでこのディレクトリへ移動して実行します。

```sh
./run.sh
```

ビルドだけ行う場合:

```sh
./run.sh --build
```

生成物は `AIBOUMonitor.app` です。`run.sh` はローカル実行用のad-hoc署名を行います。Developer ID署名、公証、配布用インストーラは含まれず、この生成物をそのまま本番配布する想定ではありません。

テスト:

```sh
./test.sh
```

テストはCPU・I/O差分、PID再利用、ファイル走査、履歴の保持範囲、CSV/plist解析、コマンド中断、デバイス情報などを検証します。管理者認証が成功する経路そのものは自動テストしません。

## 画面と取得範囲

基本監視は通常2秒間隔、詳細モードは1秒間隔です。ストレージ走査や `nettop`、`powermetrics` は通常監視から分離されています。「基本監視を停止」は基本監視とnettopを止めます。開始済みの単発電力計測は完了する場合があり、結果には取得時刻を表示します。ファイル走査には別の停止操作があります。アプリ終了時はすべての収集に停止を要求します。

| タブ | 基本表示 | 主な制約 |
|---|---|---|
| ストレージ | デバイスI/O、プロセスI/O、選択したフォルダの階層とサイズ | 全ディスク走査は別操作。保護領域は読み取れない場合がある |
| CPU | 論理コア別・全体・プロセス別CPU、スレッド、親PID | プロセスCPUは1コア使用で100% |
| GPU | `powermetrics` が返したGPU関連フィールド | GPU占有率へ推測変換しない。機種・権限依存 |
| クロック | タイマー間隔、スリープ差、壁時計差 | 動作周波数は対応する `powermetrics` 出力がある場合のみ |
| メモリ | RAM・VM・スワップ、プロセスの常駐量とフットプリント | 完全なプロセス別内訳、RAM帯域・レイテンシは取得不可 |
| ファン・温度 | OSのサーマル状態、公開される場合のセンサー値 | Apple Siliconでは温度・RPMの安定した公開APIがない |
| バッテリー | 残量、充電、確認できる絶対容量、電圧・電流・電力 | VRM温度・電力密度は取得不可。アダプタ定格と実電力を区別 |
| ネットワーク | 物理IF集計とIF別統計、明示操作によるプロセス・接続詳細 | `nettop` の形式・権限・OS版に依存。RTTはTCPの値 |
| ディスプレイ | 画素/論理解像度、設定Hz、EDID概要 | 設定Hzは実表示FPSではない |
| 外部機器 | USB・Thunderbolt機器と接続変化 | IORegistryが公開する範囲のみ。シリアル番号は収集しない |
| ハードウェア | Macモデル、CPU、RAM、OS、ストレージ等 | 非公開の部品型番は推測しない |

通常権限で基本監視を行います。フルディスクアクセスを許可すると、ストレージ走査で読める範囲が広がる場合がありますが、すべての保護領域を読める保証はありません。管理者認証を伴う追加電力計測はユーザーが明示的に実行した場合だけ起動します。`powermetrics` の対応サンプラーと出力項目は機種・OSで異なります。

追加コマンドの取消・終了・時間切れ時は、直接起動したプロセスに停止を要求し、1秒後も生存していれば強制終了を要求します。アプリ終了時はこの処理と保存に共通の最大2秒を与えます（終了保証ではありません）。管理者経路の直接プロセスは `osascript` です。認証先の `powermetrics` まで終了したことは未検証で、開始済みの1回計測が完了する場合があります。直接プロセスの終了確認と、認証先の終了保証は区別しています。

ストレージ走査は隠しファイルやアプリ内部を含め、シンボリックリンクを辿らず、ハードリンクの二重計上を避けます。保存対象は完了した走査結果だけです。途中・中断・失敗した走査は保存せず、以前の完了結果を保持します。保存中・成功・失敗は画面に表示します。

走査中は件数と合計を表示し、完了・中断後に階層を500件ずつ閲覧できます。50万件、メタデータ見積もり128 MiB、読み取りエラー1万件のいずれかに達すると理由を示して中断します。128 MiBは実メモリ使用量の上限ではありません。エラー詳細は先頭256件まで保持します。保存ファイルの上限は256 MiBです。旧版の上限超過ファイルは変更せず復元エラーを表示するため、範囲を絞った再走査が必要です。ネットワーク共有等でOSのファイル読み取りが待機している間は、停止要求の反映が遅れる場合があります。

履歴は全体集計だけを10秒間隔で端末内に最大24時間保存します。復元時も現在の集計項目の許可リストを適用します。プロセス別の値、実行パス、接続先は保存せず、起動中のメモリだけに保持します。保存は停止・削除できます。画面を閉じると基本監視を止め、追加コマンドと走査へ停止を要求します。保存待機はメインスレッドを塞がず最大2秒で終了します。保存が間に合わない場合は前回の保存結果が残ることがあります。

## 実装構成

- `Sources/Observations.swift` — 画面ラベルを含まないCodable観測値モデル
- `Sources/Common.swift` — タブ、指標、状態、表の共通モデル
- `Sources/CoreSampler.swift` — CPU、メモリ、クロック、ネットワーク、ディスクとプロセスの基本収集
- `Sources/DeviceSampler.swift` — 熱状態、バッテリー、ディスプレイ、外部機器、ハードウェア
- `Sources/StorageScanner.swift` — 停止・再開可能なファイル階層走査とアプリ関連フォルダ
- `Sources/AdditionalCollectors.swift` — `nettop` と `powermetrics` の明示的な追加収集
- `Sources/History.swift` — 24時間の集計履歴とローカル保存
- `Sources/MonitorStore.swift` — 収集周期、休止・復帰、保存、画面状態の調停
- `Sources/Diagnostics.swift` — 欠損・鮮度・監視区間・継続時間を扱う自動チェック
- `Sources/DiagnosticCatalog.swift` — 70ケースの症状・原因候補・対処・出典
- `Sources/DiagnosticsView.swift` — 状態チェック、検索、絞り込み、確認済み操作
- `Sources/App.swift` — SwiftUI/AppKitの数値検証画面

取得方法と既知の限界は [SOURCES.md](SOURCES.md) にまとめています。

最初の要望との対応状況と収集項目の一覧は [CAPABILITIES.md](CAPABILITIES.md) を参照してください。

## レビュー修正

[最新の修正内容・検証結果・残る制約](QA/R3_FIX_RESULTS.md)を参照してください。将来のアバター側では `MonitorStore.observationSnapshot()` から最新値を取得できます。`MonitoringEngine.collectObservations(interval:)` を直接使う場合は単一の直列経路から呼び出してください。収集内部の表示モデル依存は一部残っています。

ObservationはschemaVersion 2です。`collection.state` は基本監視の `running` / `paused` / `stopped` を表し、単独のEngine取得は継続監視を意味しない `snapshot` です。`segmentID` は現在の基本監視区間、`sampleSegmentID` は保持する基本値を取得した区間です。再開直後は両者が異なる場合があります。`lastSampleAt` がnilなら基本値は未取得です。追加計測は基本監視停止後に完了する場合があるため、各指標の `recordedAt` と取得元statusも確認してください。従来の `capturedAt` は基本値の時刻（未取得時は投影時刻）です。schema 1は監視状態を持たない旧形式で、この新モデルでは復元しません。端末内の履歴・ストレージ保存形式には変更ありません。
