## 目的と今回の提供範囲

AIBOUには、自分のPCの現在の状態を見る「モニター」と、遊びながらハードウェアのしくみを発見する「展示館」の2つのホームがある。展示館は、気になる装置を選び、その装置に対応する体験へ進む場所である。女の子は各展示室の場面に登場し、短い言葉で探索へ誘う。

今回の実装対象は、総合ロビー、5つの展示室、全20入口、館内マップ、各体験の紹介、作品帳、既存の回路ゲームへの往復である。20本の完成したゲームを提供するものではない。現在プレイ可能な入口は「論理回路」であり、それ以外の19入口はテーマと案内を見られる「準備中」として表示する。

論理回路には、ふたりの準備がそろったときだけ点灯するAND回路の体験がある。既存の自由実験ではAND・OR・XORも試せる。ゲーム本体の仕様と検証は [WORKSHOP-DESIGN.md](WORKSHOP-DESIGN.md) および [QA/WORKSHOP-VERIFICATION.md](QA/WORKSHOP-VERIFICATION.md) を参照する。

## 画面と移動

| 画面 | 操作と移動先 |
|---|---|
| モニター | 上部の「展示館」から探索へ。選択中のモニタータブと計測状態は元のストアに保持する |
| 総合ロビー | A〜Eの扉から各展示室へ。「作品帳」、回路の入口または作業の再開も選べる |
| 展示室 | 4つの装置に対応する操作領域から体験の入口へ。ロビーへ戻れる |
| 体験入口 | 体験名、学ぶしくみ、相棒の言葉、公開状態を読む。回路は開始・再開でき、作り直しには確認がある |
| ゲーム | 同じ回路ストアを使ってプレイする。「展示室へ」で所属エリアに戻る |
| 館内マップ | 5室・20入口を直接選べる。閉じると開いた画面へ戻る。ロビーへの移動もできる |
| 作品帳 | 完成した回路がある場合だけ作品を表示する。作品を動かすと既存の作品詳細を開く。未完成時には最初の作品への案内を表示する |

展示室やマップを歩くための3D移動操作は設けていない。装置・看板をクリックして移動する固定視点の展示である。各入口はネイティブのButtonであり、日本語の名称と状態をアクセシビリティラベルに持つ。

マップと作品帳は同じ画面に重ねて表示する。表示中は背後の展示と上部ナビゲーションを操作不可・アクセシビリティ非表示にする。閉じるボタンにはEscapeを割り当てている。マップを開いた場合やゲームから離れた場合、進行中の4通りテストを止め、そこまでの作業は保持する。

## 見た目と操作領域

元の完成イメージは `output/exhibition-home-v3/` とユーザー添付画像。クリーム色の室内、木の机、濃色の装置、少ない影、部屋ごとの色、装置に関わる女の子のポーズを基準にする。Dの「PCの構成とデータ経路」は、通常の街の模型ではなくCPU・メモリ・SSD・GPU・画面を描いた版に合わせる。

画面は1600×900の共通座標で構成し、利用可能な縦横寸法に等比で収める。余白を設け、背景を切り抜いて表示しない。展示部分にScrollViewはなく、背景・看板・操作領域は同じ倍率で拡縮する。ウィンドウの最低寸法は展示ホームで1100×730、ゲーム表示中で1100×735を指定する。タイトルバーなどのOS側領域は別に加わる。

背景の装置名や状態をネイティブUIに重ね、ホバー時は操作領域の輪郭と明るさを変える。実際のクリック範囲は `ExhibitionLayout` の正規化座標で管理する。背景を変えたときは、その装置の見た目と範囲を再照合する必要がある。

主要なシーン素材は `Art/Exhibition/` の `lobby.png`、`area-a.png`〜`area-e.png`、`circuit-entry.png`。両アプリの `Contents/Resources/ExhibitionArt/` に複製して使う。背景が読めない場合にも、画面と移動の操作は残し、画像の読み込み失敗を表示する。

女の子の展示室ごとの姿は場面の絵に含まれる。現在の版では、その場面ごとのポーズ自体を動的に変えたり、口の動きを音声に同期させたりはしていない。下部の短い案内は表示中の部屋・入口・ホバー対象に対応し、ボタンでMacの日本語音声を再生できる。作品帳とマップには今回生成した、作品帳を持つ少女の独立素材を使う。切り抜きと控えめな呼吸は既存の描画機構を共有する。

画像はプロセス内の共有キャッシュで再利用し、ホバーごとにディスクから読み込まない。室内の常時更新タイマーや3D描画ループは使っていない。画像保持量と表示の滑らかさについて、これだけで実測性能を保証するものではない。

## 状態と保存

- `ExhibitionStore` はルートと訪問情報を持つ。ルートはロビー・展示室・入口・ゲームのいずれかである。
- 展示館の保存ファイルは `~/Library/Application Support/aibou-game-lab/exhibition-v1.json`。訪問した入口のIDと、最後のロビー／展示室だけを保存する。
- 再起動では最後の展示室へ戻り、入口やゲームを自動では開かない。回路を再開する操作はプレイヤーが選ぶ。
- `CircuitLabStore` とその `WorkshopStore` は、単体版では `ExhibitionAppView`、モニター統合版では `MonitorWindow` が保持する。ゲームの出入りで盤面を新規生成しない。
- ゲームの作業・完成品は既存の `workshop-v1.json` に保存する。訪問情報からゲームの完了を推測しない。
- 「作品あり」は実際の `completedArtifact` がある場合だけ表示する。単にテストに合格しただけで、作品保存前なら作品ありとはしない。
- 未実装の入口は、訪問済みでも常に準備中。作品帳の「入口を見学」は完成数と分けて表示する。
- JSONは一時書き込みからの置換で保存する。未知の入口IDは取り除き、未知の展示室はロビーへ戻す。未知の保存形式・壊れたJSON・64KiB超の記録は読み込み失敗として扱う。
- 読めない記録は次の保存前に元のバイト列を別名で残す。保存できない場合は画面上に再試行を出し、現在のセッションの探索は続けられる。
- モニターと展示館の選択は、モニター側UserDefaultsの `aibou.destination` に記録する。これは展示館の場所やゲームの盤面とは別である。

## ビルドと検証の再現

以下はリポジトリのルート `/Users/fujishima/aibou` から実行する。

```sh
# 単体版とモニター統合版。--build は起動を行わない。
./game-lab/run.sh --build
./monitor/run.sh --build

# コアのルール・カタログ・保存モデルを検証
swift test --package-path game-lab

# GUIを操作せず、実際の展示館ストアと隔離ファイルを検証
xcrun swiftc -swift-version 5 -warnings-as-errors \
  -target "$(uname -m)-apple-macosx13.0" \
  game-lab/Sources/Core/*.swift \
  game-lab/Sources/UI/ExhibitionStore.swift \
  game-lab/Tests/StoreChecks/ExhibitionStoreChecks.swift \
  -o /tmp/aibou-exhibition-store-checks
/tmp/aibou-exhibition-store-checks

# 実際のデスクトップを使う展示館UIテスト
./game-lab/ui-test.sh test \
  -only-testing:AIBOUGameLabUITests/ExhibitionUITests
```

単体版を通常起動すると展示館を開く。従来の回路画面を直接確認したい場合は `--workshop`、自由実験は `--sandbox` を付ける。テストでは `--exhibition-save <path>` と `--workshop-save <path>` を指定し、実際の利用者の訪問・作品データを使わない。`--mute` は既存ゲームの音声・効果音を抑制する。

### 最終確認と今後の開発

最終成果物については、両バンドルに7つのシーン画像がそろうこと、20入口の到達、地図・作品帳の復帰、ゲーム作業の再開、最小寸法での操作位置、ホイールによる不動、キーボード操作を実際のUIで確かめる。キーによるフォーカス表示と、モーション抑制設定の反映は目視確認も必要である。

今後のゲーム本体の制作では、準備中の入口を一本ずつ公開する。公開時はカタログのフラグだけでなく、ゲームへのルーティング、保存モデル、理解を確かめる課題、作品帳への統合を揃える。関連するモニター指標へ案内する経路、場面内で動く装置や女の子、専用の効果音・表情・口の同期は、現在のホーム実装を土台に追加する範囲である。
