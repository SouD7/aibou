# aibou — 展示館

相棒の女の子とPCのしくみを巡る、macOS用の展示館です。総合ロビーから5つの展示室へ進み、机・棚・壁の装置を選ぶと、それぞれの体験の入口が開きます。館内マップには全20体験を配置しています。

全20体験を展示館から起動できます。各体験には5課題（回路は5チェックポイント）、ヒント、比較、予想と発見、保存再開、作品コピーがあります。今回の単独化では、そのゲーム内容・操作・画像・音・保存仕様を変更していません。

既存のAND・OR・XORの3実験は、画面上の「自由実験」から引き続き遊べます。相棒と進める展示と自由実験には、それぞれ独立した作業盤面があります。

## 女の子から教わる20の授業

ロビーの女の子にカーソルを合わせると「aibouに教わる」が現れ、クリックで授業ノートが開きます。上部の「授業」からも入れます。5分野・各4テーマを自由に選び、短い説明、操作できる模型、理由を確かめる3択、自分のPCへのつながりを順に体験します。

保存とメモリ解放、キャッシュ、圧縮とスワップ、CPUの命令、時間分割、並列処理、GPU、通信、電力など、全20テーマに授業と実験を用意しました。実験の条件は模型のもので、PCの実測値ではありません。参考資料は各授業の下部から開けます。

一度実験を操作し、問いに正答して「発見を残す」を押すと発見済みになります。間違えたときは理由を読み、答え直したり実験へ戻ったりできます。「発見済み」はこの体験を終えた記録で、習熟度の認定ではありません。関連する展示や別の授業へ進めます。

女の子は歓迎・説明・発見の3枚の静止差分を場面に合わせて切り替えます。授業中の身体の揺れや口パクはありません。ロビーは従来の瞬きのみを保持しています。音声はスピーカーを押したときだけ再生し、画面や段階を変えると止まります。

授業の記録は `~/Library/Application Support/aibou-game-lab/lessons-v1.json` に保存します。再起動後は発見済みと前の授業への入口を復元し、授業を自動で開始しません。隔離したテスト用の保存先は `--lesson-save <path>` で指定できます。回路・作品帳の記録とは独立しています。

教材の出典と対応表は [授業カリキュラム](Docs/lessons/curriculum.md)、体験の選定理由は [体験設計の調査](Docs/lessons/experience-design.md)、素材の来歴は [女の子の差分制作記録](Docs/art/lessons/manifest.md) にあります。

## 遊ぶ

単独のゲームとして起動：

```sh
./game-lab/run.sh
```

生成された `game-lab/AIBOUGameLab.app` を開くこともできます。ビルドにはXcodeとPython 3、実行にはmacOS 13以降が必要です。外部パッケージのダウンロードは不要です。

`game-lab/` フォルダだけを別の場所へコピーしてもビルドできます。フォルダ内からは `./run.sh` を実行してください。従来使っていたアバターのコードと素材は、内容を変えず [Vendor/AvatarMotion/](Vendor/AvatarMotion/README.md) に同梱しました。

ラボへのボタン・コールバックと、ラボ／モニタへのビルド依存はありません。教材本文は原文を維持しているため、「ラボ」に言及する説明文は残っています。PCの状態を収集する処理は含まれません。

展示館では「総合ロビー → 展示室 → 体験入口 → ゲーム」と進みます。「展示室へ」で所属エリアへ戻り、ロビーの「つづきから」で回路を直接再開できます。館内マップと作品帳は開いた場所へ戻ります。マップの全20入口は直接選べます。画面を縦横にスクロールせず、部屋全体とクリック範囲を一緒に縮小します。

従来の回路工房を直接開く場合は、ビルド後に `open game-lab/AIBOUGameLab.app --args --workshop` を実行します。以下はその工房の操作です：

1. 入口の「一緒にはじめる」から、ふたりの準備完了ランプを作り始めます。最初は部品を番号で表示し、働きを試して選べるようにしています。
2. パーツをクリック、または中央へドラッグして置きます。
3. 丸い端子を順にクリック、端子から端子へドラッグ、または3箇所の「つなぐ」でA・B・出力を接続します。接続済みの道を再操作すると切断できます。
4. A・Bを切り替え、ランプを観察します。「Bを入れてもらう／切ってもらう」で相棒にも実験を手伝ってもらえます。未接続は `?`、消灯は `0`、点灯は `1` です。
5. 「今の結果を残す」で観察ノートへ記録します。「4通りテスト」（⌘Return）は4条件を順番に試します。途中で止めたり、編集へ戻ったりできます。
6. 目標との食い違いが出たら「この条件で試す」で盤面に再現し、部品を交換します。「一緒に考える」から段階的なヒントを読めます。
7. 全4条件が一致すると、ANDの働きを振り返り、作品帳へ保存できます。「別の場面で予想する」は任意で、誤答しても作品を残せます。
8. 作品帳では保存した回路と観察記録を見返し、A・Bを独立に切り替えて動きを試せます。作品帳内の操作は作業中の回路へ影響しません。

盤面・部品棚・観察ノートはスクロールせず、画面内に固定します。小さいウィンドウでは作業台全体が縮小されます。「操作」の説明とテスト結果は重ねて表示する別パネルで、閉じても部品の位置は変わりません。結果は上部の「結果」から再表示できます。

「一手戻す」（⌘Z）は直前の操作を戻します。作品を残した時点が区切りとなり、保存した作品をundoで消すことはできません。「最初から」は現在の作業を片づけ、新しい作業を始めます。完成した作品は残り、前の作業へundoで戻ることはできません。

自由実験には従来の「1条件ずつ」「4条件を確かめる」、反例の再現、任意の予想、操作記録の書き出し・再生があります。自由実験の盤面はその起動中に保持し、終了後の自動再開は相棒と進める展示が対象です。

## 保存と再開

20体験の記録は `~/Library/Application Support/aibou-game-lab/experiences/<体験ID>-v1.json` に保存します。`--experience-save-dir <directory>` でテスト用の保存先を指定できます。従来の工房・展示館・授業の保存先も変更していません。

展示館の見学した入口と最後の展示室は `~/Library/Application Support/aibou-game-lab/exhibition-v1.json` に保存します。再起動では最後の部屋を開き、ゲームを自動開始しません。見学数と学習の完成は別に管理し、作品帳には実際に完成した回路だけを載せます。

展示では操作のたびに、このMacへ回路・観察・進行・最後の完成作品を保存します。次に開くと「続きから」で再開できます。中断した自動テストが勝手に再開することはありません。

```text
~/Library/Application Support/aibou-game-lab/workshop-v1.json
```

保存内容は検証可能な操作列です。現行の展示モデルは `workshop-2`、回路モデルは `circuit-2`。保存形式のファイル名にある `v1` とモデル版は別です。読めない記録は新しく始めるときに別名で残し、保存できない場合は画面に再試行の操作を表示します。

「最初から」で操作記録を短縮し、最後の作品を通常の配置・配線・検証操作から再構成します。8,192操作の上限に達した場合も、この操作で新しい作業へ進めます。短縮後も作品の回路・入力・予想・観察は保持し、内部の操作カウンタだけが更新されます。

## 画風・相棒・音

ロビー・5展示室・回路入口は、新たに画像生成した `Art/Exhibition/` の原画を使います。作品帳とマップの女の子も今回の生成素材です。部屋では女の子が装置に触れたり部品を見せたりするポーズを取り、下部の短い字幕で案内します。場面の人物は原画として固定され、作品帳の単体イラストには控えめな呼吸の動きを付けています。

看板の文字、20入口、マップ、進行表示、ボタンはSwiftUIで実装しています。ホバー時の縁取りと浮き上がり、画面のフェードを持ち、OS／アプリのモーション抑制設定を反映します。案内の音声はスピーカーボタンを押したときに再生します。

今回の全生成プロンプトと素材の来歴は [素材の制作記録](Docs/art/exhibition/manifest.json)と[生成プロンプト](Docs/art/exhibition/prompts.json) にあります。内蔵画像生成で制作し、Blenderや3D実行環境はこの版では必要ありません。

参考の「シグナル工房」に合わせ、描かれた作業机の上で、厚みのある白い部品と暗い作業マットを操作する画面にしています。

- `Art/workbench-v1.png`：生成した作業机の背景。
- `Art/guide-presenting-v1.png`：既存の相棒を参考に生成した案内用イラスト。導入では上半身と手、作業中は顔のポートレートを表示します。
- 部品、ネジ、スイッチ、信号線、観察表、操作ボタン：SwiftUIで描画する操作可能なUI。1の信号はシアンの発光、0は実線、未接続は薄い点線と `?` で区別します。

画像とネイティブの操作部品を組み合わせているため、配線や判定は実際のゲーム状態に連動します。生成時のプロンプトは `Art/*.prompt.json`、画風の参考資料は `Art/References/` にあります。

相棒は短い字幕で説明・ヒント・反例・完成を案内します。任意の音声はMacにある日本語音声による読み上げです。「音声オン／オフ」、再生・停止、操作音、動きを抑える設定を用意しています。声を聞き終える前でも操作できます。

現在の案内イラストには穏やかな呼吸の動きを付けています。顔の表情を描き替えるアニメーションや、口形のリップシンクは実装していません。動きを抑える設定や非表示時には呼吸の動きを止めます。

## 自動テスト

展示館の確認結果は[展示館QA記録](QA/EXHIBITION-VERIFICATION.md)、回路ゲームの確認結果は[回路QA記録](QA/WORKSHOP-VERIFICATION.md)にまとめています。

単独化の検証結果と実行したUIテストは [単独パッケージ検証](QA/STANDALONE-VERIFICATION.md) に記録しています。旧UIテストには現在の20体験と合わない期待が残っているため、全UIテスト成功とは扱っていません。

画面から分離したゲームモデルのテスト：

```sh
./game-lab/test.sh
```

本物のウィンドウを操作するUIテスト：

```sh
./game-lab/run.sh --build
./game-lab/ui-test.sh test
```

展示館だけのテストは `./game-lab/ui-test.sh test -only-testing:AIBOUGameLabUITests/ExhibitionUITests`。回路単独の従来画面は `open game-lab/AIBOUGameLab.app --args --workshop`、自由実験からは `--sandbox` で開けます。隔離した記録で確認する場合は `--exhibition-save <path> --workshop-save <path> --lesson-save <path> --experience-save-dir <directory> --mute` を指定します。

UIテストは現在のMacデスクトップを使います。Xcode 26に付属するテストrunnerの最低OSはmacOS 14です。アプリ本体の最低OSとは別です。テスト結果は `QA/results/*.xcresult` に保存します。[UIテストの構成](QA/TEST-SETUP.md)を参照してください。

## 性能を調べる

単独アプリを起動してから、Time Profilerで対象プロセスを記録します。

```sh
./game-lab/profile.sh 10
```

`QA/profiles/` に `.trace` と目次XMLを保存します。記録中にパーツ選択や入力切り替えを行い、Instrumentsで処理時間を調べられます。この計測だけでFPSや学習効果まで判定したことにはしません。

## 状態と操作の再現

「自由実験」の画面右下で「開発用の記録」を開くと、「状態・操作を書き出す」と「記録を再生」が使えます。保存先は以下です。

```text
~/Library/Application Support/aibou-game-lab/Exports/<日時>/
  state.json   現在の回路・検証結果・予想の回答
  replay.json  初期seed・モデル版・操作列
```

「記録を再生」は最後に書き出したファイルを読み、通常のモデル処理で操作列を実行します。画面操作によるクリアとは別の、内部状態の再現検証です。

CLIからも再現できます。

```sh
cd game-lab
swift run GameLabCLI demo QA/replay-fixture
swift run GameLabCLI replay QA/replay-fixture/demo-replay.json QA/replay-fixture/replayed-state.json
cmp QA/replay-fixture/demo-state.json QA/replay-fixture/replayed-state.json
```

書き出した自由実験の `replay.json` もCLIで読み込めます。このCLIの対象は回路モデルで、展示の `workshop-v1.json` とは形式が異なります。モデル版が違う記録、壊れた形式、不正な進行操作はエラーとして扱います。最大1万操作。seedは予想課題の入力条件に使います。現行モデルは `circuit-2` です。

このモデルの `step` は「次の真理値表の一条件を試す」操作です。物理的な信号遅延やCPUのクロックを模擬するものではありません。`tick` は受理した操作数で、時間やフレーム数ではありません。

## 実装の構成

| 場所 | 役割 |
|---|---|
| `Sources/Core/` | 回路の論理・判定・seed・replay、展示の進行・undo・作品保存 |
| `Sources/UI/` | 作業台、相棒の字幕・音声・イラスト、作品帳、自由実験 |
| `Vendor/AvatarMotion/` | 従来のアバターコード・素材の固定コピー |
| `Art/` | 背景と案内イラスト、生成プロンプト、参考資料 |
| `scripts/` | アバター素材の準備、操作音の生成 |
| `Sources/App/` | 単独実行用のアプリ入口 |
| `Sources/GameLabCLI/` | JSONによる状態取得と操作再生 |
| `Tests/CoreTests/` | 真理値表・進行・未接続・反例・undo・作品保持・上限回復・再生の検証 |
| `UITests/` | XCUIAutomationによる実画面の操作検証 |

部品名・配線・操作ボタンにはアクセシビリティ識別子を付けています。テスト専用に正解画面へ移動する経路はありません。

## 到達範囲

全20体験と20授業を含み、従来の回路工房・AND／OR／XORの自由実験も保持しています。電圧・電流・伝播遅延を省いた理想的な論理モデルで、未接続は保守的に「不明」と扱います。

ソフトウェアとしての確認結果は[QA記録](QA/WORKSHOP-VERIFICATION.md)、今回の進行と評価項目は[展示設計](WORKSHOP-DESIGN.md)、従来の3実験の目標は[学習設計](LEARNING-DESIGN.md)を参照してください。初心者の楽しさ・学習効果はまだ実測していません。
