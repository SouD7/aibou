# aibou — ハードウェア理解をゲーム化するための既存作品リサーチ

調査日：2026-09-14  
対応資料：[ゲーム化する理解の範囲](AIBOU_GAME_LEARNING_SCOPE.md)

## 1. 調査の目的と読み方

20の学習テーマを起点に、参考となる既存ゲームを調査した。作品名だけでなく、**原作でプレイヤーが何をするか、その操作を使ってaibouでは何を理解できるようにするか**を整理する。

ここで「単発」は、一つの画面・課題・ステージとして参照できる体験とする。作品全体が短編という意味には限定していない。長い作品は、参考にする一場面と、取り除く必要のある要素を示した。

主候補20件と補助候補6件を掲載する。収録ミニゲームや追加コンテンツも含む。広く流通する商用作品を中心に、題材に直接合うブラウザゲームや小規模作品を加えた。知名度の数値比較や売上順位を示すリストではない。

調査は開発元の公式サイト、開発元・販売元のストア説明、公式マニュアルに基づく。今回、実際のプレイ、所要時間の測定、学習効果の検証は行っていない。

- **原作の遊び**：一次資料で確認できた内容。
- **aibouへの応用**：本調査からの設計提案。原作に同じ課題が存在するという意味ではない。
- **直接**：原作が対象の概念そのものを扱う。ただし学習テーマ全体を満たすとは限らない。
- **比喩**：別の題材の操作・制約・フィードバックを、ハードウェアの理解に使う。
- **単発化「高」**：一問・一盤・少数の操作へ絞りやすい。「中」：設定や課題の整理が必要。「低」：前提となるシステムが多い。いずれも企画上の評価。

## 2. 優先して見る作品

初期の学習範囲Aに対応する調査は、次の8件から始めると、異なる遊び方を比較しやすい。

| 作品 | 見るべき点 | 学習テーマ |
|---|---|---|
| Cisco Binary Game | 0・1を切り替えると、表す数が変わる即時の対応 | H02 |
| NandGame | 仕様に合う回路を作り、できた部品を次の課題へ使う | H03・H04 |
| Turing Complete | 回路・記憶・CPU・命令が、段階的につながる構成 | H03〜H05・H01 |
| Human Resource Machine | 命令、手元の値、記憶場所を、キャラクターの動きで見せる | H05・H06の一部 |
| Memory Management | 複数の仕事に、限られたRAMの領域を割り当てる | H07・H06の一部 |
| Overcooked! | 前後関係のある仕事を分担し、同時に進める楽しさ | H07・H08・H20への比喩 |
| shapez - Puzzle DLC | 大きな自動化ゲームを、固定空間・部品制限の一問へまとめる | H20・H08への比喩 |
| PC Building Simulator 2 | 部品や設定を変え、温度・電力・性能を再計測する | H01・H16・H17の一部 |

この順は作品の優劣ではなく、学習目標Aを起点にした確認順である。並列処理を深めるなら7 Billion Humans、配置とアクセスならWilmot’s Warehouse、電力ならPower to the People、映像なら「フレームレートクイズ」を追加する。以下に各作品の出典と用途を示す。

## 3. 回路・記憶・命令を理解する6候補

### G01 Cisco Binary Game

**原作の遊び。** ビットを切り替えて指定された数を表したり、ビット列に対応する十進数を入力したりする。ゲーム内に桁の重みが示される。[Cisco公式ゲーム](https://learningcontent.cisco.com/games/binary/index.html)

**aibouへの応用。** H02に直接対応。「3個のスイッチで8種類を区別し、9種類目のために何を増やすか考える」一題にする。数字から色や記号の表現へつなぐ部分は、新たに設計する。

**単発化：高。** 一問の操作が小さい。最初は時間制限を外す案がよい。原作の中心は二進数の変換練習なので、計算が速いことだけを学習目標にしない。

### G02 NandGame

**原作の遊び。** 部品を配置・配線して指定の機能を作り、できた部品を次の課題に使う。公式のゲーム用説明では、ラッチ、フリップフロップ、レジスタ、RAMなどの課題も確認できる。[公式ゲーム](https://nandgame.com/)

**aibouへの応用。** H03・H04に直接対応。「指定の条件で点く回路」「書込みの合図が来たときだけ値を覚える箱」を別の一題にする。完成した部品を触ってから内部を開ける入口も考えられる。

**単発化：高。** 目標の入出力と、現在の結果を比べる構成が参考になる。リレーや論理部品のモデルと、現代PCの物理的な実装の違いを補う。

### G03 Turing Complete

**原作の遊び。** 論理ゲートを組み合わせ、記憶を持つ部品、CPU、自分のハードウェア上の命令・プログラムへ進む。[公式紹介](https://turingcomplete.game/)

**aibouへの応用。** H03〜H05に直接対応し、H01の全体像へつなぐ参考。「二つの0・1を足し、和と桁上がりを表示する」程度の小さな回路を一題にする。作品全体からは、以前の発見が次の仕組みに使える構成を学ぶ。

**単発化：小回路は高、CPU全体は中。** CPUの完成は複数の展示をつなぐ到達先として扱う。原作全体を一つのミニゲームへ圧縮しようとすると、前提が増えすぎる。

### G04 Human Resource Machine

**原作の遊び。** 命令を並べ、社員に仕事をさせる。開発者は、入出力箱、床の記憶場所、手元に保持する値というコンピュータとの対応を説明している。正解後には命令数や実行速度を改善できる。[開発元の公式紹介](https://tomorrowcorporation.com/humanresourcemachine)

**aibouへの応用。** 対応関係が明示された比喩として、H05の第一候補。「値を受け取る→一時的に置く→計算する→出力する」を数種類の命令カードで表す。H06の作業中の記憶への入口にもなる。

**単発化：高。** 命令と動きの対応が見える。床の記憶場所を、電源OFF後も保存されるストレージの学習と同一視しない。永続保存を扱うには別のルールが必要。

### G05 TIS-100

**原作の遊び。** 架空の計算機の複数ノードへ命令を書き、入力から目的の出力を作る。ポート経由の読み書きは、相手が対応する操作を行うまで待つ。[公式紹介](https://www.zachtronics.com/tis-100/)、[公式マニュアル](https://www.zachtronics.com/images/TIS-100P%20Reference%20Manual.pdf)

**aibouへの応用。** H05・H08の発展。「二つの係が互いに受取りを待っている状態を、命令の順序変更で動かす」一題にする。計算中・受取り待ち・送り待ちを見分ける表現を参考にする。

**単発化：中。** 原作の命令入力とマニュアルには導入が必要。aibouでは二つの係と少数の操作に絞る。架空のノードを、現代CPUのコアそのものとして説明しない。

### G06 ChipWizard Professional（Last Call BBS収録）

**原作の遊び。** 配線・トランジスタ・コンデンサを用いて集積回路を作る、収録ゲームの一つ。[開発元の公式紹介](https://www.zachtronics.com/last-call-bbs/)

**aibouへの応用。** H19・H03の深掘り。「制御入力を変えると、どの経路がつながるかを予想する」一題の表現を検討する。複数の独立ゲームへ同じ空間からアクセスする構成も参考になる。

**単発化：中。** 個別問題の詳細な操作・達成判定は、今回の紹介資料だけでは未確認。既存の特定ステージをそのまま推薦する段階ではなく、回路の見せ方を次に詳しく確かめる候補。

## 4. データ・仕事・並列化を理解する7候補

### G07 Memory Management（boxoforeos）

**原作の遊び。** プロセスの要求を、RAM内の空き領域へドラッグして割り当てる。分かれた空き領域をまとめるCompactionもある。作者公開のゲームジャム・プロトタイプ。[作者の公開ページ](https://boxoforeos.itch.io/memory-management)

**aibouへの応用。** H07、H06・H10の容量制約という一部に直接対応。「RAMが4枠しかないとき、複数の仕事をどう入れ替えて進めるか」という題材の参考にする。

**単発化：高、導入と終了条件は再設計。** 小規模作品であり、知名度を理由に選んだ候補ではない。領域を整理するCompactionはデータ圧縮と異なる。原作に保存・スワップがあるとは確認できていない。

### G08 Wilmot’s Warehouse

**原作の遊び。** 倉庫の商品を自分なりに配置・分類し、要求された品を素早く取り出す。[公式ストア説明](https://store.steampowered.com/app/839870/Wilmots_Warehouse/)

**aibouへの応用。** H09への比喩。「よく使うデータを、近くの小さい置き場に選んで置く」課題へ応用する。繰り返し同じデータを使う場合と、毎回違うデータを使う場合を比較する。

**単発化：高。** 商品数と要求列を固定する。近い小容量の層と遠い大容量の層、取得時間、データの置換はaibouで加える仕組み。原作の倉庫がキャッシュを再現しているわけではない。

### G09 7 Billion Humans

**原作の遊び。** 多数の作業者が同時に実行する手順を作る、ステージ制のプログラミングパズル。[開発元の公式紹介](https://tomorrowcorporation.com/7billionhumans)

**aibouへの応用。** H08の並列処理を扱う直接の参考。H12のGPUには比喩として使う。「別々の画像を処理する仕事」と「前の計算結果を必要とする仕事」で、作業者を増やした効果を比較する。

**単発化：高。** 少人数・少数命令で比較できる。作業者一人と実機のコア・GPU演算器を一対一に対応づけない。実機への説明にはデータ転送や分割の負担も補う。

### G10 Opus Magnum

**原作の遊び。** 複数の部品やアームで錬金術の機械を作り、目標の製品を生産する。同じ結果に対して速さやコンパクトさなどを改善する。[開発元の公式紹介](https://www.zachtronics.com/opus-magnum/)

**aibouへの応用。** H08・H20への比喩。「運ぶ・処理する・受け取る」の順序を合わせ、二つの担当を同時に動かしてよい箇所を見つける。完成後の短い再生と、複数の改善軸を参考にする。

**単発化：高。** アーム二つ程度に絞る。錬金術や機械同士の衝突は独自のルールなので、原作の動きをそのままCPUの仕組みと説明しない。

### G11 EXAPUNKS

**原作の遊び。** EXAという実行主体をプログラムして、場所を移り、ファイルを操作する。公式の問題作成資料では、ホスト、リンク、ファイル、ハードウェアレジスタや入出力を区別できる。[公式紹介](https://www.zachtronics.com/exapunks/)、[公式の問題作成資料](https://www.zachtronics.com/virtualnetwork/)

**aibouへの応用。** H05・H08、H06・H11の前提となるデータ操作の参考。「計算係は空いているのに、必要なデータがまだ届いていない」状態を見えるようにする。

**単発化：中。** 操作する主体・データ・場所を分ける点が有用。ハードウェアレジスタという名称だけで、CPU内部レジスタ・RAM・SSDの比較を教える作品と解釈しない。永続性やI/O性能のルールは別途必要。

### G12 Overcooked!

**原作の遊び。** 注文に応じて、下準備・調理・提供を分担する料理ゲーム。1〜4人で遊ぶ。[Team17公式紹介](https://www.team17.com/games/overcooked)

**aibouへの応用。** H07・H08・H20への比喩。「人を増やすか、特定の工程を増やすか」で処理の進み方を比べる。手順の前後関係と、複数の仕事を同時に進める楽しさを参考にする。

**単発化：高。** 一つの厨房・少数の注文へ絞る。aibouでは移動の反射速度に評価が偏らないよう、割り当て後に自動実行する形式も検討する。人間の連携ミスをPCの仕組みと混同しない。

### G13 shapez／shapez - Puzzle DLC

**原作の遊び。** 本編では加工と搬送を組み合わせて図形を生産する。Puzzle DLCは、空間・建物・入力となる形や色を制限して指定の図形を作る独立した問題形式。問題作成機能もある。[本編の公式説明](https://store.steampowered.com/app/1318690/shapez/)、[Puzzle DLCの公式説明](https://store.steampowered.com/app/1625400/shapez__Puzzle_DLC/)

**aibouへの応用。** H20・H07・H08への比喩。「読み込み→計算→出力」の小さな流れを用意し、一か所だけ変更して完成量が変わるか比較する。加工装置を増やす場合と、搬送を速める場合の差を発見させる。

**単発化：高。** 特に参考にしたいのは、システム全体を固定条件の一問へまとめるDLCの構成。DLCは単独ソフトではなく本編が必要。帯域や律速の比較課題はaibou側の提案であり、DLCの全問題がそれを教えるという意味ではない。

## 5. 通信・映像を理解する3候補

### G14 Mini Metro

**原作の遊び。** 駅の間に路線を引いて列車を走らせ、街の成長に応じて経路と限られた資源の配分を変える。[開発元の公式紹介](https://dinopoloclub.com/games/)

**aibouへの応用。** H14・H07・H20への比喩。固定した少数地点でデータを届ける課題にし、一度に運べる量と到着までの時間を別々に変える。

**単発化：中。** 本編は継続型なので、要求数・地点数・終了条件を固定する。原作が帯域と遅延を独立に操作して教えるとは確認していない。鉄道の運行とパケット通信は同一ではない。

### G15 Net（Simon Tatham’s Portable Puzzle Collection）

**原作の遊び。** タイルを回転し、ループのない一つの接続網を完成させる。中心につながるタイルが点灯する。[作者のルール説明](https://www.chiark.greenend.org.uk/~sgtatham/puzzles/doc/net.html)、[ブラウザ版](https://www.chiark.greenend.org.uk/~sgtatham/puzzles/js/net.html)

**aibouへの応用。** H14・H17の接続・到達性への部分的参考。「つなぐと届く、切ると届かなくなる」を一操作で確かめる。接続した範囲が光るフィードバックを参考にする。

**単発化：高。** もともと一盤完結。通信性能や端子の互換性まで学ぶには追加の条件が必要。原作のループ禁止を現実の回路・ネットワークの共通原則として扱わない。

### G16 Nintendo Switch 2 のひみつ展：フレームレートクイズ

**原作の遊び。** 流れる映像のフレームレートを当てるミニゲーム。別枠には、スライダーで映像の見え方を変えるスーパーレゾリューションの技術デモもある。[任天堂公式](https://www.nintendo.com/jp/games/switch2/aahea/index.html)

**aibouへの応用。** H13の体感に直接対応。「同じ動きを異なる頻度で見比べ、予想し、条件を変えて確かめる」構成を参考にする。解像度は別の一題に分ける。

**単発化：高。** すでに独立したミニゲーム。FPSと画面のHzの区別まで原作のクイズ単体で教えるとは確認していない。実際に比較できる表示は使用画面の能力に制約される。技術デモと、クリア目標を持つゲームも区別する。

## 6. 実物PC・電力・熱を理解する4候補

### G17 PC Building Simulator 2

**原作の遊び。** PCを組み立て、修理・改善する。公式の機能説明には、部品の消費電力を示すPowerMonitor、Fan Control、Thermal app、ベンチマークがある。[公式機能紹介](https://www.pcbuildingsim.com/news/pc-building-simulator-2-is-out-now)

**aibouへの応用。** H01・H16・H17の一部に直接対応。「動くPCを観察→変更を一つ選ぶ→再計測」の一題にする。温度・電力・仕事の速さが、どう変わったかを比較する。

**単発化：中。** 完成したPC一台と一件の改善課題から始める。部品を選び組み立てる全手順は、短い因果比較の前提にしない。SoCやユニファイドメモリを直接学ぶ教材としては不足する。

### G18 Power to the People

**原作の遊び。** 変化する都市の電力需要に対して、発電・蓄電・電力の流れを管理する。[開発元の公式紹介](https://www.rhombicogames.com/game/power-to-the-people/)

**aibouへの応用。** H15への比喩。供給できる速さ、使う速さ、貯まっている量を別々に見せる。「仕事の実行時刻を変え、残量を保ちながら決められた仕事を終える」一題にする。

**単発化：中。** 都市・経営・研究を外し、固定時間の需給だけを取り出す。原作の発電所や電力網の数値をPCへ移植しない。PCの充電制御を扱う場合は別の根拠が必要。

### G19 Oxygen Not Included

**原作の遊び。** 宇宙コロニーを維持し、設備、電力、配管、周囲温度や発熱を管理する。[開発元掲載の公式ストア説明](https://store.steampowered.com/app/457140/Oxygen_Not_Included/)

**aibouへの応用。** H16への比喩。「熱を出す装置を動かし続け、冷却条件で時間経過後の状態がどう変わるか」を確かめる。熱がたまるまでの時間差を見せる発想が参考になる。

**単発化：低〜中。** 原作の学習範囲は大きい。熱源・周囲・放熱だけに絞る再設計が必要。原作の熱のルールが現実のPCを正確に再現すると解釈しない。

### G20 Circuit Jam

**原作の遊び。** 配線、部品値、スイッチを操作し、指定された電気信号を作る個別パズル。電圧・電流・抵抗・静電容量などを扱う。[開発元掲載の公式ストア説明](https://play.google.com/store/apps/details?id=com.circuitjam)

**aibouへの応用。** H15・H19に隣接する電気回路の入口。「目標の出力→回路を変更→結果の差を観察」という一題の構成を参考にする。

**単発化：高。** 原作自体が個別パズル。ただし中心はアナログ回路であり、論理ゲート・トランジスタやPCのバッテリーを直接教える候補とは扱わない。電気の基礎を追加する場合の参考。

## 8. リサーチから得られた設計上の判断

### 既存作品を参考にしやすい領域

**ビット、論理回路、記憶回路、命令実行、並列処理**は、その概念自体を遊びとして扱う参考がある。操作、導入の順序、失敗の見せ方を比較し、aibouに必要な一題へ絞る作業を進めやすい。

**仕事の共有、キャッシュ、通信、ボトルネック、電力、熱**は、物流・料理・工場・都市・コロニーなどの遊びが参考になる。何を操作し、何を観察するかを取り出し、ハードウェア側の意味と対応させる設計が必要。

### 独自設計の比重が大きい領域

今回の調査では、次の理解をそのまま一式扱う適切な既存ゲームは確認できなかった。

1. **RAMと永続保存の違い**：作業場と保存先、保存操作、電源OFFを一つの体験で対比すること。
2. **メモリ圧縮とスワップ**：容量を節約する代わりの処理、退避と再読込みの待ちを見せること。
3. **ストレージの容量と性能の違い**：保存できる量と、読み書きにかかる時間を独立に変えること。
4. **SoC・ユニファイドメモリ**：機能が統合され、経路やメモリを共有すること。
5. **端子の形と対応機能の違い**：挿さることと、必要な通信・映像・給電ができることを区別すること。

これは「作品が存在しない」という結論ではなく、今回確認した候補での空白である。例えばRAMのゲームは、Memory Managementの「割当て」、HRMの「一時保持」、Wilmotの「配置と取り出し」を参考にし、保存・電源OFFのルールをaibouで加える方針が考えられる。

## 9. 単発ゲームの企画に落とす例

以下はすべてaibou向けの新しい課題案であり、原作内のステージ名ではない。

| 仮の問い | 参考作品 | 一題でプレイヤーがすること | クリア後に確かめる理解 |
|---|---|---|---|
| 9種類目の目印はどう作る？ | Cisco Binary Game | 3ビットの組み合わせを使い切り、表現できる種類を増やす | ビットを一つ増やすと、組み合わせはどう変わるか |
| 入力が消えても覚えていられる？ | NandGame、Turing Complete | 保持と書込みを切り替える仕組みを作る | 今の入力と、保持した状態の違い |
| 先に置かないと足せない？ | Human Resource Machine | 値を一時的に保持し、命令の順序を直して計算する | 命令・データ・記憶場所の関係 |
| 保存先を増やせば仕事は入る？ | Memory Management、HRM、Wilmot | RAMと保存先を別々に増やし、作業できる条件を比べる | RAM容量と保存容量は何を制約するか |
| 4人なら何でも4倍速い？ | 7 Billion Humans、Opus Magnum | 独立した仕事と、前の結果を待つ仕事を人数違いで動かす | 並列化できる条件と、人数を増やしても残る待ち |
| よく使うものはどこに置く？ | Wilmot’s Warehouse | 近い小さな置き場に残すデータを選ぶ | アクセスの繰り返しと配置が取得時間に与える影響 |
| 遅い場所はどこ？ | shapez - Puzzle DLC、Mini Metro | 完成済みの流れを観察し、一つの条件だけ変える | 別の仕事でも同じ変更が有効か |
| 速く動かし続けられる？ | PC Building Simulator 2、Power to the People | 仕事・冷却・給電の条件を変え、継続後の状態を比べる | 瞬間的な速さと、熱・電力の制約の関係 |

この段階で固定するのは、問い・操作・得たい気づきである。キャラクター、舞台、制限時間、報酬、難易度は、試作を通して決める。
