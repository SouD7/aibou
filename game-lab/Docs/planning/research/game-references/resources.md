# 資源・データ移動・並列処理のゲーム参考調査

調査日：2026-09-14。対象は学習範囲設計書の H06・H07・H08・H09・H10・H11・H12・H20。公式サイト、開発元のストア説明、公式の制作資料を確認した机上調査であり、今回の実機プレイによる検証ではない。

ここでの「単発」は、作品全体が短編という意味に限定せず、一つのステージ・固定した課題・一つの仕掛けをミニゲームの参考として取り出せること、とする。以下の「aibouの一題」は本調査の設計案であり、既存ゲーム内にその名前や課題が存在するという主張ではない。「直接」は扱う概念自体に対応するもの、「類推」は操作や制約の構造を別の題材へ応用するものを指す。

## 先に押さえたい結論

- H08 並列処理には **7 Billion Humans**、H20 ボトルネックには **shapez** が特に有力。
- **shapez - Puzzle DLC** は、空間・建物・入力の種類を制限した個別問題を用意するため、無限に拡張する工場全体よりも「短い一題」の構成を参照しやすい。
- **Wilmot’s Warehouse** は H09 の「よく使うものの配置と取り出す負担」の類推として有力。ただし実際のキャッシュ、RAM、保存装置を再現する作品ではない。
- H06 の揮発性／永続保存の違い、H10 の圧縮・退避・再読込みを、そのまま一式学べる有名な作品は今回の資料調査では確認できなかった。H11 の容量と速度の区別も直接の好例は未確認。既存作が教える内容として水増しせず、aibou側で必要なルールを設計する領域である。
- H12 GPUには 7 Billion Humans の「多数の実行主体に似た仕事を配る」構造を応用できる。ただしGPUの実機モデルを教える作品とは扱わない。

## 1. 7 Billion Humans

**公式資料で確認できること**：プレイヤーは多数の作業者を動かすプログラムをつくる。前作の一人による実行から進み、多数の作業者が同時に実行できる言語を採用した、ステージ制のプログラミングパズルである。ヒントとスキップ機能も用意される。[開発元](https://tomorrowcorporation.com/7billionhumans)

**参考になる理由**：並列処理を「複数の進行が同じ画面で見える動き」に変換できる。H08の独立した仕事と、他の結果を待つ仕事を比較する入口として強い。H12への応用は類推であり、GPUの内部構成をそのまま見せる参考ではない。

**aibouの一題案**：「4人に増やすと、どの仕事が速くなる？」。同じ手順で独立した4枚の絵の色を変える仕事と、前の結果を使って次の値を出す仕事を比べる。実行人数だけを変え、終了までの刻みを予想してから再生する。H12へ進むときは、画像の多数の画素へ同じ処理を配る一題に発展させる。

**短編化**：移動・読込み・一つの計算・出力程度に命令を絞り、既に途中までできている手順を修正する形式なら入口を短くできる。

**誤解と初心者障壁**：人数をPCのコア数やGPUの演算器数へ一対一対応させない。仕事の分割、依存関係、データを渡す時間を省くと「増やせば比例して速くなる」と誤解させる。初心者には条件分岐・反復の理解が別途必要になるため、最初から自由記述させるより選択肢を限定する。

## 2. shapez／shapez - Puzzle DLC

**公式資料で確認できること**：shapez本編は、図形を採取・切断・結合・積層・着色し、目的の形を生産する自動化ゲームである。生産量を増やし、処理の流れを拡張・改善する。Puzzle DLCでは使える空間・建物・形や色を制限し、指定の図形をつくる問題へ縮小している。独自問題を作成できるエディターがある。[本編の公式ストア説明](https://store.steampowered.com/app/1318690/shapez/)、[Puzzle DLCの公式説明](https://store.steampowered.com/app/1625400/shapez__Puzzle_DLC/)

**参考になる理由**：CPU相当の加工装置だけを増やしても、入力・運搬・後工程が追いつかなければ全体が速くならない、というH20の類推に向く。処理量と待ちを同じ盤面に表示しやすい。H08の同じ工程を複数に分ける体験や、H07の共有経路の混雑にもつなげられる。

**aibouの一題案**：「遅い場所はどこ？」。読込み→加工→出力の3区間を置く。加工装置を増やす案と、入力経路を広げる案を比較し、完成数が変わるか予想させる。別の仕事では律速する区間を変え、同じ強化がいつも有効とは限らないことを確かめる。

**短編化**：全工場をゼロから建てるのでなく、完成済みの小工場で1か所だけ変更する。「観察→仮説→一つ変更→再生」の形が適する。DLCは独立ソフトではなく本編が必要な追加コンテンツである。

**誤解と初心者障壁**：ベルトが必ずPCのバスそのもの、図形がCPU内で物理的に流れる荷物、という説明にはしない。PCのコピー・転送・並行処理には独自のルールがある。図形加工ルールとハードウェア理解を同時に学ばせると負担が増えるため、aibouでは加工を「画像に明るさを足す」など身近な処理へ置き換える。

## 3. Wilmot’s Warehouse

**公式資料で確認できること**：倉庫の品物を押す・分類する・積むなどして整理し、注文時に必要な品物を素早く取り出す。配置と分類方法はプレイヤーに任される。配送が続くと品物が増える。[公式ストア説明](https://store.steampowered.com/app/839870/Wilmots_Warehouse/)

**参考になる理由**：「どこに置くか」が「必要なとき取り出す負担」に効くことを体験できる。H09のデータへのアクセスと配置の類推として扱う。ゲーム内の倉庫自体がキャッシュやRAMというわけではない。

**aibouの一題案**：「よく使うデータを手元に置く」。注文列を先に見せ、近い小さな棚に何を置くか決める。遠い大きな棚からの取得には時間がかかる。繰り返し同じ品が必要な注文列と、毎回違う品が必要な列で効果を比較する。近い棚の容量を増やす場合と、取得順を変える場合も比較する。この二層・固定遅延モデルはaibou側で新たに加えるルールである。

**短編化**：商品数・倉庫サイズ・注文列を固定すれば、一つの配置判断を短く比較できる。

**誤解と初心者障壁**：人間が置き場所を覚えるゲーム上の記憶と、PCのメモリを同一視しない。実際のキャッシュではアクセス規則や置換処理が働く。倉庫の見た目を整えることがPCの整理・高速化に直結するという結論にしない。H06の揮発性と永続性、H10の圧縮やスワップはこの作品がそのまま教える内容ではない。

## 4. Opus Magnum

**公式資料で確認できること**：プログラム可能なアームや経路などを組み合わせ、錬金術の製品をつくる機械を設計する。正解は一つではなく、速さ・簡潔さ・コンパクトさなどを改善し、動く結果をアニメーションとして出力できる。[開発元](https://www.zachtronics.com/opus-magnum/)、[公式ストア説明](https://store.steampowered.com/app/558990/)

**参考になる理由**：一つの完成結果へ、複数の担当を協調させる設計が参考になる。H08の工程間の依存関係とH20の改善箇所を考える類推。成功して終わるだけでなく、同じ結果をより少ない手順や時間で得る再挑戦の楽しさを扱える。

**aibouの一題案**：「アームを増やしても待つのはなぜ？」。入力を運ぶ、加工する、結果を運ぶという役割を配置する。独立する運搬を同時化する場合と、加工結果を待つ運搬を同時に始めようとする場合の違いを見せる。待ちがある工程を見つけて1手だけ配置や順序を変更する。

**短編化**：入力は一種、出力は一種、アームは二つ程度に絞り、工程の前後関係だけを扱う。完成後の短い再生と前案との比較を参考にする。

**誤解と初心者障壁**：共有CPU時間のスケジューリングを直接教える作品ではない。アームの物理的干渉を、そのままスレッドやコアの挙動として表現しない。独自の錬金術ルールを覚える負担もあるため、参考にする中心は「見える動きと複数の改善軸」である。

## 5. EXAPUNKS

**公式資料で確認できること**：EXAという実行主体をプログラムし、ネットワークを移動・複製させ、ファイルの操作などを行う。公式の問題作成資料にはホスト、リンク、ファイル、ハードウェアレジスタが別要素として定義されており、ファイルの作成・移動・変更や、レジスタへの読込み・書込みを課題にできる。[開発元](https://www.zachtronics.com/exapunks/)、[公式の問題作成資料](https://www.zachtronics.com/virtualnetwork/)

**参考になる理由**：「命令を実行する主体」「データ」「データのある場所」を画面上で区別する発想が有用。H08の複数主体による処理やデータの受け渡しの発展参考となる。H06・H11についてはファイルの操作という前提概念の参考に留める。公式の問題作成資料にあるハードウェアレジスタとファイルの区別を、CPU内部レジスタとRAMとSSDの比較だと読み替えない。

**aibouの一題案**：「計算できるのに、データがない」。2か所のデータを処理場所へ集めて結果ファイルを作る。計算の手順だけでは終わらず、読込みや受け渡しが必要なことを発見する。RAMと保存先の違いを扱う段階では、この移動の見せ方に、保持期間・容量・電源OFFのルールを別途設計して加える。

**短編化**：原作の言語・命令群・物語をそのまま入口にすると重い。3種類ほどの操作カードと2か所のデータで、一つのファイル処理だけを扱う設計なら応用可能。

**誤解と初心者障壁**：EXAが移動する架空ネットワークは現実のPCのメモリ階層やプロセスモデルそのものではない。本作だけでRAMの揮発性、永続保存、スワップ、I/O性能を習得できるとは今回確認していない。公式ストアは英語のみの表記であり、命令と資料を読む負担がある。[公式ストア](https://store.steampowered.com/app/716490/EXAPUNKS/)

## 6. while True: learn()

**公式資料で確認できること**：用意されたブロックを配置・接続してデータの流れをつくり、形や色による分類を、精度・速度・費用の条件で改善する。ブロックのゲーム内の働きと実際の技術を結びつける説明が用意される。主題は機械学習である。[開発元の公式ストア説明](https://store.steampowered.com/app/619150/while_True_learn/)

**参考になる理由**：コードの記述を入口にしない、操作→実行→流れの観察→改善という体験の参考。H20の処理段階と性能改善へ類推できる。直接ハードウェアを学ぶ題材としては、上位候補より適合が弱い。

**aibouの一題案**：「同じ出力を速くつくる」。読込み・計算・保存を表すブロックを配線し、詰まっている段階を一つ選んで変更する。ブロックの短い説明では、ゲーム内の単純化とPC上の対応を併記する。このハードウェアへの置換はaibou向けの提案。

**短編化**：一つの入力と一つの目標、3ブロック程度の完成済みの流れへ限定しやすい。既存作にある世界観、仕事の受注、機械学習の歴史などまで取り込む必要はない。

**誤解と初心者障壁**：ニューラルネットワークや分類ルールの理解をハードウェア理解と混同しない。「機材をよくすれば何でも速い」と教えず、処理の依存と転送をaibou側で明示する。ブロックの名称が新しい学習負荷になるため、PCの身近な操作を表示する。
