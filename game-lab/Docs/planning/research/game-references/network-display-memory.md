# 通信・映像・小規模メモリゲームの調査メモ

調査日：2026-09-14。公式説明を確認した資料調査。実機プレイは未実施。

## Nintendo Switch 2 のひみつ展：フレームレートクイズ

- 出典：[任天堂公式](https://www.nintendo.com/jp/games/switch2/aahea/index.html)
- 確認できたこと：流れる映像のフレームレートを当てるミニゲームがある。別枠の「スーパーレゾリューションデモ」はスライダーで見え方を変える技術デモである。
- 対応：H13の映像の滑らかさに直接。FPSとHzの区別や解像度と描画負荷の因果まで、このクイズ単体で教えるとは確認していない。
- aibouへの提案：同じ動きを異なる生成頻度で表示し、見比べる→予想する→条件を変えて確かめる一題にする。解像度の比較は別の一題に分ける。
- 単発化：すでに単独のミニゲーム。入力と結果の対応をすぐ体感できる参考として優先度が高い。
- 限界：実際の表示比較は使用ディスプレイの更新能力に制約される。高い設定値を選んだだけで、実際にその頻度で表示されていると扱わない。テックデモはクリア条件のあるゲームと区別する。

## Mini Metro

- 出典：[開発元の作品紹介](https://dinopoloclub.com/games/)、[公式ストア](https://store.steampowered.com/app/287980/Mini_Metro/)
- 確認できたこと：駅の間に路線を描いて列車を走らせ、街の成長に合わせて路線を引き直し、限られた資源を配分するゲーム。
- 対応：H07・H14・H20への構造の類推。経路・輸送能力・混雑を見て配置を変える操作を参考にする。
- aibouへの提案：固定した少数の地点間でデータを運ぶ課題にし、一度に運べる量と到着までの時間を別々に変えて比較する。
- 単発化：本編は街が成長する継続型。地点と要求数を固定し、指定件数を届ければ終了する一題への再設計が必要。
- 限界：鉄道の乗客輸送はパケット通信そのものではない。帯域と遅延の独立した操作、パケットや再送の意味はaibouで追加する設計であり、原作にあると主張しない。

## Net（Simon Tatham's Portable Puzzle Collection）

- 出典：[作者のルール説明](https://www.chiark.greenend.org.uk/~sgtatham/puzzles/doc/net.html)、[ブラウザ版](https://www.chiark.greenend.org.uk/~sgtatham/puzzles/js/net.html)
- 確認できたこと：タイルを回転させ、閉じたループのない一つの接続網を完成させる。中心につながるタイルが点灯する。小さな盤面を指定できる。
- 対応：H14・H17の接続・到達性への部分的参考。H18の端子機能・給電能力を教えるゲームではない。
- aibouへの提案：少数の部品を接続するとデータの到達先が点灯し、接続の違いを観察できる一題にする。
- 単発化：もともと一盤完結。回転という一操作、接続部分が光る即時フィードバックを参考にしやすい。
- 限界：原作の「ループ禁止」はパズルのルール。現実の回路やネットワークの共通原則として教えない。信号の処理、通信速度、互換性は別に設計する必要がある。
- 補足：[KNetWalk公式](https://apps.kde.org/knetwalk/)にも、サーバーと端末を接続する同系統のゲームがある。重複を避け、主一覧ではNetを代表にする。

## Memory Management（boxoforeos）

- 出典：[作者の公開ページ](https://boxoforeos.itch.io/memory-management)
- 確認できたこと：プロセスのメモリ要求をRAM内の空き領域にドラッグして割り当てる。空き領域が分かれていて要求が入らない場合、Compactionで一つの大きな空き領域へまとめる。作者はゲームジャムのプロトタイプで、十分なチュートリアルを実装できなかったと説明している。公開形式はHTML5。
- 対応：H07の資源割当、H06・H10のRAM容量制約という一部分に直接。保存の永続性、圧縮、スワップを扱うとは確認できない。
- aibouへの提案：決められたRAM容量に複数の仕事の作業領域を割り当て、同時に実行できる仕事が変わる一題を参考にする。
- 単発化：操作と画面の範囲は小さい。明確な終了条件と導入の作り直しが必要。
- 限界：知名度を根拠に選んだ作品ではなく、題材の直接性を理由に加えた補足候補。Compaction（領域の移動・整理）とメモリ圧縮（データ表現を小さくすること）を混同しない。現代のmacOSのRAM管理を、そのままこの連続領域のモデルで説明しない。

## Overcooked!

- 出典：[Team17公式作品紹介](https://www.team17.com/games/overcooked)
- 確認できたこと：1〜4人で注文に応じて下準備、調理、提供を進める料理ゲーム。複数のキッチンを舞台にする。
- 対応：H07・H08・H20への構造の類推。複数の仕事を分担し、手順の前後関係を考える遊びを参考にする。
- aibouへの提案：下準備→加熱→提供の少数工程を持つ仕事を固定し、担当者や設備の割当を変えて完了時間を比較する。人を増やすだけでなく、どの工程を増やすと効くかを問いにする。
- 単発化：一つのキッチンを一題の参考にできる。aibouでは移動操作の巧拙と資源配分の理解を分けるため、配置・指示後に自動実行する方式も検討する。
- 限界：人間の連携ミスや反射速度による失敗はCPU内部の処理とは異なる。厨房をそのままPCのモデルと呼ばず、依存関係と共有資源という構造だけを取り入れる。
