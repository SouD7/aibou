# aibou ゲーム参考調査：ビット・回路・命令実行

調査日：2026-09-14。対象：H02、H03、H04、H05、H19。補助的にH08も含む。

本調査では「単発」を、一画面・一課題・一つの仕掛けとして切り出せるゲーム体験と解釈した。市販作品全体が短時間で終わる、という意味ではない。公式の紹介、公式マニュアル、公式サイト配信のゲーム内説明を調べたもので、実際のプレイや学習効果の測定は行っていない。「aibou案」「短編化しやすさ」「初心者障壁」は調査からの設計判断である。知名度・販売数の順位は調べておらず、専門性の高い作品を一般に有名だとは扱わない。

## 選定結果

| 作品 | 対応する理解 | aibouで参考にする中心 | 短編化の判断 |
|---|---|---|---|
| Cisco Binary Game | H02に直接対応 | ビットを切り替え、数との対応を即座に確かめる | 高：一問だけで成立。ただし情報表現全般への拡張が必要 |
| NandGame | H03・H04に直接、H05へ接続。H19はリレーの類推 | 一つの仕様を満たす部品を作り、完成部品を次に使う | 高：ゲート一つ、記憶一ビットに区切れる |
| Turing Complete | H03・H04・H05に直接対応 | 回路→記憶→CPU→命令がつながる発見 | 中〜高：全体は長い。初歩の一課題を切り出す |
| Human Resource Machine | H05に対応するコンピュータの比喩 | 命令・データ・保持場所をキャラクターの動きで見せる | 高：命令を数種類に限定した一仕事 |
| TIS-100 | H05に直接、H08の一部にも対応 | 一命令ずつ進め、値と通信待ちの原因を追う | 中：入力する命令とノード数を減らす必要 |
| ChipWizard Professional（Last Call BBS内） | H19・H03に直接対応 | 配線・トランジスタで集積回路を作る独立ゲーム | 中：一つのスイッチ動作まで単純化が必要 |
| KOHCTPYKTOP: Engineer of the People | H19・H03に直接対応する参考 | 半導体回路を仕様から設計する遊び | 低〜中：難しさと現在の動作環境に確認事項 |

ここで「直接」は、作品自体がその概念を扱っていることを表す。現実のPCを完全に再現する、または遊べば理解が保証される、という評価ではない。

## 1. Cisco Binary Game

**公式で確認した遊び**：ビットを切り替えて右側の数値を表す問題と、表示されたビット列に対応する十進数を入力する問題がある。素早く問題を解いて得点する構成。8桁に対応する128〜1の重みを示す。画面とゲーム内Instructionsは、Cisco配信のページと配信スクリプトで確認した。[公式ゲーム](https://learningcontent.cisco.com/games/binary/index.html)

**参考になる理解**：H02「0・1の組み合わせと表現可能な状態数」。同じ画面の中で0・1の操作と数の変化が対応する。ただし原作の中心は二進数と十進数の変換練習であり、「音・色・文字も符号化できる」までの学習は今回確認していない。

**aibou用に切り出す一題（独自案）**：「3個のスイッチで8種類の荷物に別々の目印をつける。9種類目が来たら、どうする？」。各組み合わせと対象を対応させ、スイッチを一つ増やすと何種類増えるか予想してもらう。数値変換だけで終わらせず、同じビット列の解釈を色や記号に変更する後続課題も考えられる。

**短編化・初心者障壁**：一画面の一問として扱いやすい。最初は3ビット程度で、時間制限なしにする案が適切。桁の重みを知らない初心者に速度だけを要求すると、理解より暗算の負荷が先に立つ。

**避けたい誤解**：ビットは数値専用である／0・1そのものに固定された意味がある／変換が速いことが情報表現の理解と同義である。

## 2. NandGame

**公式で確認した遊び**：仕様に合う部品を、部品の配置と配線によって作る。完成した部品は次の課題に使える。現行の最初の課題は、リレーでNANDを作るもの。入力を切り替えて回路への影響を観察し、仕様に合うか検証する。公式サイトが配信する説明にはSR Latch、D Latch、Data Flip-Flop、Register、RAMもあり、保持・書込み・更新タイミングを段階的に扱っている。[公式ゲーム](https://nandgame.com/)

**参考になる理解**：H03「論理を組み合わせる」、H04「入力が変わっても過去の値を保持する」。CPUまで積み上げる流れはH05への接続に使える。最初のリレー体験はH19の「制御されるスイッチ」の類推にはなるが、トランジスタそのものではない。

**aibou用に切り出す一題（独自案）**：「書込みスイッチを押したときだけ、ランプが入力の色を覚える箱を完成させる」。まず完成した記憶部品で保持と書込みを体験し、興味があればその内部の配線へ進む。初見から帰還回路をゼロから作らせるかは別途試作で判断する。

**短編化・初心者障壁**：仕様一つ、入力二つ程度の独立課題にしやすい。真理値表と配線記号を同時に初めて見る人には負荷があるので、身近な動作の目標も併記したい。学びの順序や部品の再利用の参考として優先度が高い。

**避けたい誤解**：ラッチで保持することと電源を切っても保存されることを混同する／リレーが現代PC内部の基本部品である／ゲームの簡略化した電気モデルを実際の全回路へそのまま当てはめる。

## 3. Turing Complete

**公式で確認した遊び**：NANDから論理ゲートを作り、記憶を導入した部品、CPU構成、自分のハードウェア上の命令やプログラムへ進む。シリーズのパズルとして算術・メモリ・CPUの関係を扱い、自作回路やコンピュータを作るシミュレータを備える。[公式紹介](https://turingcomplete.game/)、[公式Steamページ](https://store.steampowered.com/app/1444480/Turing_Complete/)

**参考になる理解**：H03・H04・H05を分断せず、前に作ったものが次の仕組みを可能にする、と体験できる。原作全体を遊ばせる構成をそのまま採用すると長い学習経路になるため、aibouでは独立した展示と接続して扱いたい。

**aibou用に切り出す一題（独自案）**：「二つの0・1を足し、結果を二つのランプで表示する」。0+0、0+1、1+0、1+1をすべて通るように配線する。1+1の場面で、一つの出力だけでは足りない理由を発見する。これはaibouの課題案であり、原作内の特定ステージの再現調査ではない。

**短編化・初心者障壁**：一ゲートや小さな算術回路は切り出しやすい。CPU全体をゼロから組む体験は、展示一つに圧縮するより複数の短編がつながった到達先として扱う方が自然。文字情報、回路図、配線自由度が同時に増える点が初心者向け調整の対象。

**避けたい誤解**：現実のPCの性能・電力・通信・保存装置まで、NANDの機能モデルだけで説明し尽くせる／ゲーム内で一つのCPUを完成すれば、現代CPUの細部を理解したことになる。

## 4. Human Resource Machine

**公式で確認した遊び**：上司から与えられた仕事を、ドラッグ＆ドロップの命令列で社員に実行させる。INBOX・OUTBOXが入出力、床の置き場所がメモリ、手に持つ一箱がアキュムレータという対応が、開発者自身によって明示されている。最初は少数の命令で、段階的に増える。正しく仕事を終えることに加え、命令数と実行速度の最適化目標がある。[開発元の公式紹介](https://tomorrowcorporation.com/humanresourcemachine)

**参考になる理解**：H05「小さな命令を順番に実行し、保持した値を利用する」。外見はオフィスの比喩だが、参考にする対応関係は明確。記憶の『使い方』も表すが、H04の『記憶回路を作る』理解をこれ単独で扱えるわけではない。

**aibou用に切り出す一題（独自案）**：「二つの数を受け取り、先の数を一時置き場に置き、合計を出す」。命令カードを並べる。実行中に現在の命令、手元の値、置き場の値を同時に見せ、順序を入れ替えるとどこで困るかを比較する。

**短編化・初心者障壁**：初心者向けの入口として最優先。キャラクターの動作を理解の手がかりにでき、読み書き・計算・出力だけの短編に絞れる。後半のプログラミング課題まで必須にしない。

**避けたい誤解**：床の置き場所と現実のRAMの構造が同一／アプリにある一つの操作がCPU命令一個で終わる／すべてのCPUが手元一個の値だけで動く。比喩の対応と簡略化をゲーム後に短く接続する。

## 5. TIS-100

**公式で確認した遊び**：架空の計算機のプログラムを書き換え、与えられた処理を行わせる。命令やレジスタ、複数ノード間の通信を扱い、サイクル数・命令数・ノード数の最適化を競える。公式マニュアルでは、ポートを使う命令は相手側の読出し・書込みが成立するまで待つと説明されている。[公式紹介](https://www.zachtronics.com/tis-100/)、[公式マニュアル](https://www.zachtronics.com/images/TIS-100P%20Reference%20Manual.pdf)

**参考になる理解**：H05「命令と値の状態を追う」、補助的にH08「別々の仕事でも通信待ちがある」。ただしTIS-100のノード接続は架空の機械の規則であり、現代CPUの全コアが同じ方法で通信していることを示す教材ではない。

**aibou用に切り出す一題（独自案）**：「二つの計算係が、どちらも先に受取りを待って停止している。片方の命令順を直し、データを渡して結果を出す」。読む・計算する・送るの三種のカードと、二つのノードだけで構成する。実行状態を『計算中』『受取り待ち』『送り待ち』として表示する。

**短編化・初心者障壁**：待ちが目に見える仕組みは有用。原作の文字入力とマニュアル前提の体験をそのまま採用すると難しい。H05の入門はHuman Resource Machine、通信待ちの発展は本作、と分担する案を推す。

**避けたい誤解**：ノードを追加すれば必ず速くなる／ゲーム内のサイクル数や命令規則がそのまま実機の時間・命令になる。

## 6. ChipWizard Professional（Last Call BBS内）

**公式で確認した遊び**：Last Call BBSに収録されたゲームの一つで、配線・トランジスタ・コンデンサを使って集積回路を作る。複数の独立ゲームが一つの架空のPCから開けるという全体構成も、aibouの展示群に参考になる。個別ステージの詳細な達成判定・入力波形・操作の細部は今回の公式紹介だけでは確認していない。[開発元の公式紹介](https://www.zachtronics.com/last-call-bbs/)、[公式Steamページ](https://store.steampowered.com/app/1511780/Last_Call_BBS/)

**参考になる理解**：H19「制御されるスイッチから論理が生まれる」、H03「部品の組み合わせが論理動作になる」。H19を扱う次の実機確認候補として優先する。

**aibou用に切り出す一題（独自案）**：「入力をONにすると出口がOFFになる、反転するスイッチを作る」。最初は既成の二種類のスイッチ部品を使い、動く部分だけを見せる。内部の物理モデルや詳しい部品配置は発展展示に分ける。これは原作の既存ステージ名・課題の紹介ではない。

**短編化・初心者障壁**：独立したゲームとして収録される形式は参考になる。ただし回路の部材を最初から一括で扱うのは難しいと考えられ、一つのスイッチか一つの論理に絞った試作が必要。

**避けたい誤解**：ゲームの集積回路モデルが製造工程やアナログな電気特性をすべて表している／すべてのデジタル信号で1=電流あり、0=電流なしと言い切る。

## 7. KOHCTPYKTOP: Engineer of the People

**公式で確認した遊び**：半導体工場のエンジニアとして、渡された仕様に合わせた集積回路を設計する。開発者は難しい作品であること、後半は実際の回路を元にする課題が多いことを明記している。公式ページはゲーム内チュートリアル動画が多くのブラウザで動かないとも案内する。[公式紹介](https://www.zachtronics.com/kohctpyktop-engineer-of-the-people/)

**参考になる理解**：H19・H03の深掘り。半導体回路に踏み込む作品の先行例として残す。ただし現在の環境でのプレイ可否、個別問題の操作・達成判定は未確認。現時点で「今すぐそのまま遊べる初心者向けゲーム」としては推さない。

**aibou用に切り出す一題（独自案）**：「制御入力を一つ切り替えたとき、どの経路がつながるかを予想してから実行する」。複雑な集積回路を作らせる前に、制御と導通の因果を小さく体験させる。これは原作の問題を確認して再現したものではない。

**短編化・初心者障壁**：原作を直接小型化するより、ChipWizardと合わせて制御されるスイッチの見せ方を調べる補助資料にする。

**避けたい誤解**：本作の抽象化をそのまま現代の半導体製造・全回路の説明に使うこと。

## 主候補にしなかった作品

- **MHRD**：ハードウェア記述言語で仕様に合う回路を書き、シミュレーションと検証を行い、完成部品を再利用してCPUを作る。テーマ適合は高いが、今回の入口ではNandGame・Turing Completeと重なり、文字でハードウェア記述を行う負荷が加わる。文字による回路設計を発展機能にする場合の追加候補。[公式Steamページ](https://store.steampowered.com/app/576030/MHRD/)
- **SHENZHEN I/O**：マイクロコントローラ、メモリ、論理ゲートを組み合わせ、アセンブリで製品を動かす。部品とソフトの関係に有用だが、仕様書・複数部品・命令の同時導入を要するため初期の短編の主候補から外した。組込み機器を扱う発展テーマに適する。[公式紹介](https://www.zachtronics.com/shenzhen-io/)、[開発元の教育向け説明](https://www.zachtronics.com/zachademics/)

## 親資料へ渡す結論

最初に深く見るべきは、**H02=Cisco Binary Game、H03・H04=NandGameとTuring Complete、H05=Human Resource Machine**。この四つで「表す→組み合わせる→覚える→命令で動かす」の異なる操作を比較できる。TIS-100は待ちと並行動作への発展、ChipWizard Professionalは物理的なスイッチへの深掘りに回す。KOHCTPYKTOPは歴史的・専門的な補助参考。

特にaibouへ持ち込みたいのは、**結果を見ながら0・1を変える／仕様を満たすようにつなぐ／状態を保持する／命令を並べて実行を追う**という四種の操作。これは原作の見た目を真似る提案ではなく、学習目標に対応するゲーム操作の抽出である。
