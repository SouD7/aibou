# 論理回路 — 導入から「ふたりの準備ランプ」まで

更新日：2026-09-14。今回の実装範囲、採用した画風、案内の設計意図、評価基準をまとめる。最終の画面・UIテスト・性能確認の件数と合否は、`QA/WORKSHOP-VERIFICATION.md` に記録する。本書は試験の合格記録ではない。

## この体験で完成させるもの

使用者とaibouの彼女が一つずつ準備スイッチを持ち、「ふたりとも準備できたときだけ光るランプ」を作る。彼女は依頼・操作案内・共同実験・振り返り・再開案内を担当し、使用者は部品を置き、つなぎ、結果を比較して回路を直す。

初回は入力、出力、接続、0と1、二つの条件が両方必要になる仕組みを扱う。最後にこの働きをANDと名づけ、完成した作品を保存する。既存のAND・OR・XORの3実験は「自由実験」に残し、相棒との展示から往復できる。OR・XORの案内付き展示、NOT、複数部品、計算機は今回の完成範囲に含めない。

「遊べた」証拠と「理解できた」証拠は分ける。自動テストによる完了は実装検証であり、初心者の楽しさや学習効果の実測ではない。

## 現在実装している体験

- **作る。** 初回の部品はパーツ01・02・03として表示する。クリックかドラッグで配置し、3本の配線を端子のクリック・ドラッグ・「つなぐ」ボタンから操作できる。スイッチAは使用者、Bは相棒の準備を表す。
- **一緒に試す。** 相棒への依頼でBだけを切り替える。入力を直接変えることもできる。ヒントは本人が求めると段階的に詳しくなり、必要なら具体的な部品候補まで案内する。
- **観察する。** 現在の入力と結果をノートへ残せる。4通りの自動テストは順次表示し、途中停止・編集・画面離脱に対応する。中止後の再テストは次の検証条件から巡回するため、必ず00から始まる演出とはしていない。
- **食い違いから直す。** 現在の回路で得た反例を表示し、その入力を盤面に再現できる。部品や配線を変えると、古い回路の観察・判定を無効にする。
- **完成を残す。** 全4条件が合えばANDの働きを説明する。別の場面での予想は任意で、誤答でも保存へ進める。作品帳は保存した回路・接続・入力・観察から表示し、作品内のA・Bだけを切り替えて何度も試せる。
- **中断して戻る。** 操作のたびにMac内へ保存し、次回は続きから始められる。終了時に進行していた自動テストは勝手に再開しない。

完成時の保存はundoの区切りとなり、その前へ戻って作品を消すことはできない。「最初から」も新しい作業の区切りで、前の作業へundoでは戻らない。最後の作品は保持する。このとき操作記録を短い通常操作列へ組み直し、8,192操作に達した場合も新しい作業へ進める。作品の回路と観察を保持し、内部の操作カウンタを短縮後の値へ更新する。読み込み時は任意の成功snapshotを信頼せず、操作列から状態を検証して再構成する。

展示の自動保存は `~/Library/Application Support/aibou-game-lab/workshop-v1.json`、モデル版は `workshop-2`。保存できない場合は画面に表示し、再試行できる。自由実験の盤面は独立しており、その起動中に保持する。

## 採用した画風と相棒の見せ方

参考画像「シグナル工房」の、机に置かれた物理的な部品を触る印象へ寄せる。淡い机、濃いgraphiteの方眼マット、面取りされた白い機器、ネジや厚い側面、シアンの合図で構成する。下部の部品トレイも暗い機器のように描き、3つのチップを選べるようにする。

背景は生成画像 `Art/workbench-v1.png`、案内役は既存の相棒を参考に生成した `Art/guide-presenting-v1.png` を使う。画面の文字・部品・配線・ノート・ボタンは操作可能なネイティブUIとして重ねる。背景画像自体に正解の配線や状態を焼き込まず、実際のモデルの入力・接続・出力が表示を決める。

導入では案内する手と上半身を見せ、実験中はコンパクトな顔と字幕を表示する。相棒を大きく表示する操作も用意する。現在のイラストの動きは穏やかな呼吸で、発話中は動きの周期をわずかに変える。顔の表情・視線・手を個別に動かす仕組みや、口形のリップシンクは実装していない。

音声は任意で、Macにインストールされている日本語音声による読み上げを使う。字幕、読み上げの停止・再生、音声と操作音のオン／オフ、動きを抑える設定がある。聞き終わるまで操作を止めず、通常の入力変更では声を繰り返さずに字幕を状態へ合わせる。非表示時は案内の読み上げと呼吸を止める。

## 導入から作品まで

以下は体験の流れである。スイッチ観察などを別々の強制画面に分けず、一つの作業台で本人の順番で試せるようにしている。

| 場面 | 使用者ができること | 彼女の役割 | 次へ進める根拠 |
|---|---|---|---|
| 依頼 | 作るものを知り、開始する | 二人の準備ランプを依頼する | 使用者が始める意思を示す |
| スイッチの観察 | A・Bを切り替える。0/1と準備状態の関係を見る | 自分のBを紹介し、依頼されたときに操作する | 準備前と準備完了が表示で区別できる |
| 部品と配線 | 部品を選ぶ。接続・切断する。一手戻す | 端子へ注意を向け、操作を短く伝える | 部品と3本の接続がそろう |
| 自由な実験 | 好きな順番で入力を変え、光り方を観察する | 見守る。質問されたら比較条件を示す | 次の実験や全条件テストを本人が選ぶ |
| 全条件テスト | 4通りを順番に見る。中止して編集へ戻る | テスト開始を宣言し、必要なところだけ説明する | 現在の回路の全4条件が評価済み |
| 食い違いの観察 | 反例を盤面で再現する。部品を交換する | 実際に起きたことと依頼の違いを指す | 使用者が編集・再テストできる |
| 完成と名前 | 作ったランプを動かす。振り返りを見る | 成功を喜び、ANDという名前を紹介する | 現在の回路の全条件が一致する |
| 任意の予想 | 別の言葉で同じ条件を考える。あとで試す | 予想の根拠と観察を結びつける | 正誤に関係なく作品へ進める |
| 作品帳 | 完成した回路と観察を見る。作品内のスイッチを動かす | 何ができるようになったかを一文で残す | 完成時点の作品が保存される |

## 彼女の台詞

台詞は1回に1〜2文を基本とし、操作対象・盤面の実際の状態・次に選べることを結びつける。操作中は盤面を隠さず、台詞の終了を操作の前提にしない。字幕で同じ情報を得られ、読み上げの停止・再生・無音を選べる。

以下の台詞表は設計時のコピー例と介入の指針であり、全項目を独立したイベントとして実装した台本ではない。実際の表示文言は `Sources/Core/WorkshopSession.swift` と `Sources/UI/WorkshopStore.swift`、画面内の説明は `Sources/UI/WorkshopView.swift` が定義する。

### 最初の依頼と操作

| 発生条件 | 台詞 |
|---|---|
| 初めて開く | 「ふたりの準備ができたときだけ、このランプがつくようにしたいんだ。一緒に作ってみよう？」 |
| スイッチの紹介 | 「Aはあなた、Bは私の準備スイッチ。0は準備前、1は準備できた合図だよ。」 |
| 最初の配置 | 「まずは、真ん中に部品を置いてみよう。あとから交換できるよ。」 |
| 配線の案内 | 「スイッチ、部品、ランプの間をつないでみよう。線がつながると、合図が届くよ。」 |
| 部品がない状態でヒントを求める | 「まだ、ふたつの合図を受け取る部品がないみたい。部品をひとつ置いてみよう。」 |
| 接続が足りない状態でヒントを求める | 「まだ合図が届かないところがあるね。『つなぐ』と出ている場所を確かめよう。」 |
| Bを操作してもらうボタンの説明 | 「私のスイッチも、頼んでくれたら切り替えるよ。自分で触っても大丈夫。」 |

初回の依頼文と最初のヒントでANDを指名しない。正しい候補だけを強調したり「両方なら点灯」という正解説明を選択前から添えたりしない。本人が比較して選び直せることを優先する。現在の実装では、さらにヒントを求めた場合にパーツ01を具体的に提案する。

### 入力と観察

| 発生条件 | 台詞 |
|---|---|
| 使用者の依頼でBを0→1にする | 「私も準備できたよ。ランプはどうなったかな？」 |
| 使用者の依頼でBを1→0にする | 「私の準備をいったん戻すね。光り方も変わるかな？」 |
| 配線が全部そろった直後 | 「つながったね。ふたりのスイッチを変えて、光り方を試してみよう。」 |
| A=0、B=0、出力0 | 「今はふたりとも準備前。ランプは消えているね。」 |
| A=0、B=1、出力1 | 「今は私だけ準備できているのに、ランプが光ったね。」 |
| A=1、B=0、出力1 | 「今はあなただけ準備できているのに、ランプが光ったね。」 |
| A=1、B=1、出力0 | 「ふたりとも準備できたけれど、まだランプが消えているね。」 |
| A=1、B=1、出力1 | 「ふたりとも準備できたら光ったね。片方だけのときも確かめよう。」 |

この表は全操作に読み上げを付ける指示ではない。同じ状況の繰り返しでは盤面と観察記録だけを更新し、台詞は見守りへ戻す。部品・入力・結果が一致しない台詞を履歴だけで出さない。

### 段階的なヒントと反例

| 段階 | 台詞 |
|---|---|
| ヒント1：目的へ戻る | 「光ってほしいのは、ふたりとも準備できたときだけだったね。」 |
| ヒント2：比較する条件 | 「片方だけ準備できたときと、ふたりとも準備できたときを比べてみよう。」 |
| ヒント3：試す手順 | 「まずAを0、Bを1にしてみよう。このときは、まだ光らないでほしいね。」 |
| 反例の観察へ誘う | 「目標と違った、この組み合わせをもう一度盤面で見てみよう。」 |
| OR等が片方だけで点灯した | 「片方だけでも光る部品みたい。入力をそのままにして、別の部品に替えるとどうなるかな？」 |
| XOR等が両方ONで消灯した | 「片方のときと、両方のときで光り方が違うね。ふたりとも準備できたときに光る部品を探そう。」 |
| 再テストへ | 「変更した回路で、もう一度4通りを確かめてみよう。」 |

ヒントは使用者が押したときに段階を進める。停止時間だけで誤解と決めつけず、勝手に正解へ交換しない。案内役が配線を自動実演する機能は現在含めていない。追加する場合は本人が開始し、実演の一手を戻せるようにする。

### テスト・中断・再開

| 発生条件 | 台詞 |
|---|---|
| 使用者が全条件テストを開始 | 「4通りを順番に試すね。スイッチとランプを一緒に見てみよう。」 |
| 使用者がテストを止める | 「ここで止めるね。今の状態から、また触ってみよう。」 |
| テスト中に部品・配線を編集 | 「回路が変わったので、ここでテストを止めたよ。変更した回路で確かめ直そう。」 |
| 一手戻す | 「ひとつ前に戻したよ。」 |
| 途中保存から再開 | 「おかえり。作りかけのランプを残してあるよ。続きから試してみよう。」 |
| 保存済みの完成作へ戻る | 「ふたりの準備ランプ、ここに残してあるよ。また動かしてみよう。」 |

再開時に具体的な状況を説明するなら、保存された部品・接続・入力・判定に即した文章を使う。中断されたテストを再起動時に自動実行しない。失敗結果は失敗のまま見られ、編集中なら未検証の状態で再開する。

### 完成・任意の予想・作品

| 発生条件 | 台詞 |
|---|---|
| 全条件が一致 | 「できた！ 片方だけでは光らず、ふたりとも準備できたときだけ光ったね。」 |
| 名前を紹介 | 「ふたつの条件が両方そろったときに合図を出す。これがANDの働きだよ。」 |
| 任意の予想へ | 「今度は『準備完了』と『開始許可』のランプだと考えてみよう。準備だけできているとき、光るかな？」 |
| 正答：消灯 | 「そう、まだ消えているね。開始許可もそろったら光るよ。」 |
| 誤答：点灯 | 「この条件では、まだ消えているよ。準備と開始許可の両方がそろう必要があるんだ。回路でも確かめてみよう。」 |
| 予想を見送る | 「また気になったときに試そう。」 |
| 作品保存 | 「『ふたりの準備ランプ』ができたね。作品帳に残して、いつでも動かせるようにしよう。」 |
| PCへの入口 | 「こうした小さな判断の回路を組み合わせると、計算する仕組みにつながっていくよ。」 |

予想は任意で、誤答しても完成が取り消されたり先へ進めなくなったりしない。全4条件を試した後なので「まだ試したことのない入力」とは呼ばない。作品の保存完了を伝える台詞は実際の保存成功後に出す。

## 表示と進行で守ること

- **0・1・不明を分離する。** 0は接続された信号の値で、1は別の値。未接続の `?` はまだ信号を判定できない状態。暗い色だけで0と未接続を兼ねない。
- **信号と電源を混ぜない。** 0/1はこのゲームの論理状態であり、電圧・電流の測定値ではない。「電気が来ていない」ではなく「合図が届いていない」と表現する。
- **本人が試す権利を保つ。** 彼女がBを操作するのは依頼か明示したテスト中だけ。通常の台詞が入力を変えない。
- **変更後の結果を表示する。** 部品や配線の変更で古いテスト結果を無効にする。自動テストの途中での編集、undo、離脱、再開により古い処理が再び結果を書き戻さない。
- **観察と合格を区別する。** 一度だけ点灯しても合格とはしない。任意順の観察記録がある場合も、どの回路の結果かを保持する。
- **一手戻すを理解可能にする。** 何が戻ったか盤面に反映し、台詞と判定もその状態にそろえる。保存や作品閲覧そのものを編集の一手に含めない。
- **文字と操作を隠さない。** 台詞は全文を読める。長い説明は利用者が開く。彼女の表示がランプ・配線・主要操作を覆わない。小さいウィンドウでも必要な操作へ到達できる。
- **完成作と作業中の回路を分ける。** 完成後の改造で現在の判定は未検証に戻るが、保存済みの完成作が壊れた状態へ勝手に書き換わらない。再挑戦で依頼の目的を再確認できる。

## 8つの意味のあるUI確認シナリオ

テストは通常の操作経路を使う。期待する画面だけを強制表示する検証で代用しない。

1. **初めての導入と未接続。** 初期保存のない状態で開く。彼女の依頼から開始し、スイッチを切り替える。ランプは未接続 `?` のままであり、0と同じ説明にならない。部品と3本の線を置くと同じ入力に対する0/1へ変わる。初回の案内がANDを正解として指示していない。
2. **誤った部品から反例で修正。** ORを置いて配線し、4通りを試す。片方だけ準備できた状態で点灯する反例が示される。「この入力で観察する」でその状態を再現し、部品を交換する。以前の失敗結果は新しい回路の結果として残らず、再テストで合格へ進める。
3. **一手戻して考え直す。** 接続済みの回路で入力変更→部品交換→切断を行う。undoごとに直前の盤面へ戻り、ランプ・彼女の説明・検証可否が矛盾しない。undo履歴が空になっても壊れず、そこから普通に再編集できる。
4. **彼女にBをお願いする。** A=0/B=0の接続済み回路でBへの依頼を押す。Bだけが1になり、実際のランプに即した台詞が出る。もう一度でBが0へ戻る。Aは変わらず、通常のヒントを押しても入力は変わらない。
5. **テストを中断して編集する。** 正しい回路で順次テストを開始し、完了前に中止または編集する。テストが停止し、残りのタイマーが入力や判定を書き戻さない。そのまま誤った部品へ替え、時間を置いても古い成功は出ない。改めてテストすると現在の回路で失敗する。画面を離れ戻る場合も確認する。
6. **作りかけを終了して再開する。** 部品・配線・入力を既定値と異なる状態へ変え、途中でアプリを終了して再起動する。回路と進行が一致し、彼女は続きへ案内する。テスト途中で終了した場合は自動実行せず、安全に編集または再テストできる。
7. **任意の予想を間違える・見送る。** ANDを完成させて予想を開き、意図的に誤答する。実際の条件と正しい出力を説明し、観察か作品への進行を選べる。別の試行では予想を見送る。いずれも完成を失わず、進行不能にならない。
8. **完成作が残る。** 成功から作品保存へ進む。保存した作品の名称・条件・回路・観察が一致する。作品内のA・Bを切り替えるとランプが変わり、閉じても作業盤面へ影響しない。終了後も作品を開ける。完成直後のundoや、作業盤面の改造・やり直しで完成作品を失わない。保存失敗を作れる場合は成功と誤表示せず、再保存の手段を確認する。

## 人に遊んでもらうときの問い

実装の検証後、初めて遊ぶ人に目的の説明、自由な実験、失敗からの修正、別の場面での予想をお願いする。観察するのは「彼女が話さなくても次に触るものがわかるか」「話してほしい場面と黙ってほしい場面はどこか」「両方ONの成功だけでなく片方ONの失敗条件を説明できるか」「もう少し改造してみたいか」である。これらの結果を見て台詞の長さと介入頻度を調整する。

## 固定盤面への修正

プレイ中の盤面・部品棚・観察ノートからScrollViewと結果への自動スクロールを廃止。ウィンドウが小さい場合は作業台を一括縮小し、説明・反例・完成結果は別パネルに重ねる。結果パネルは閉じて盤面を操作でき、上部の「結果」から再表示する。保存エラーもフッターから別パネルで確認する。導入や作品帳の長い読み物はプレイ盤面とは別の領域として扱う。
