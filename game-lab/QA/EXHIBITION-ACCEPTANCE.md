# 展示館ホーム：受け入れ条件

2026-09-14。ここで記すのは実装前の合格条件であり、検証済み結果ではない。最終的な実行結果と既知の制約は別途記録する。

## 提供する範囲

モニターと並ぶ展示館ホーム、ロビー、館内マップ、5室、全20体験の入口、作品帳、および既存回路ゲームへの往復。20テーマを20入口に割り当てる今回の仕様は、学習範囲文書の調査優先度や完成したゲーム数とは区別する。

現在のネイティブ実装には回路のアトリエと自由実験がある。メモリ・ドックは画像資料があるが、初期レビュー時点でプレイ可能なSwift実装は見つかっていない。未実装の入口には準備中を示し、開始できるように見せない。

## 必須の動作

| 対象 | 合格条件 | 主な検証方法 |
|---|---|---|
| 2つのホーム | モニターの選択中タブと展示館の場所を、それぞれ保持して切り替えられる。展示館をモニターの一覧サイドバーに押し込めない | モニター実機操作 |
| ロビー | A〜Eの5入口が同時に見え、各室に移動できる。初回に架空の再開・完成進捗を表示しない | UIテスト・目視 |
| 20入口 | H01〜H20が一意に1回ずつ所属する。各室に4つ、マップに20個の選択可能な入口がある | モデルテスト・UIテスト |
| マップ | 現在の画面から開ける。閉じると同じ画面に戻る。入口の直接選択は、その所属室と対応する | モデルテスト・UIテスト |
| 体験入口 | 名称・中心の問い・状態をネイティブ文字で読むことができる。準備中でも何を学ぶか確認でき、戻れる | UIテスト・目視 |
| ゲーム往復 | 回路の部品・配線・入力・観察・ヒントの状態を保って展示に戻り、再開できる。ゲーム終了で所在が迷子にならない | UIテスト |
| 保存 | 再起動後は最後の展示室と訪問情報を復元し、自動的にゲームを開始しない。入口から回路作業を再開できる。欠損・未知のID・破損した保存により起動不能にならない | モデルテスト・隔離保存によるUIテスト |
| 作品帳 | 空の場合は空と分かる。回路の完成品がある場合だけ表示し、装置や保存済み観察を確認できる。閉じたとき元の場所に戻る | UIテスト・既存作品帳テスト |
| シーン | ホイール操作で展示やクリック位置が動かない。ウィンドウサイズ変更で背景と操作位置が一致する | UIテスト・実機操作 |
| 動きと音 | 非表示・非アクティブで不要なアニメーションと読み上げが止まる。音声なしでも内容が分かる | コードレビュー・実機操作 |
| 配布物 | 単体アプリとモニターの両方に同じ画像リソースが入り、リポジトリの相対パスに依存せず起動する | 両ビルド・バンドル確認 |

## 画面品質

- 参照画面は1672×941。画像全体を等比で収め、必要なら余白を設ける。塗りつぶしによる切り抜きで左右の展示や上部表示を失わない。
- 各部屋で主展示と補助展示の大小、壁・棚・机の違いを残す。展示名のリストだけで空間を置き換えない。
- 女の子を室内に置き、同じ人物・衣服・描画の方向性を保つ。ホバーや案内表示は彼女や展示を大きく隠さない。
- 入口は装置または看板と明確に対応する。人物と重なる部分は操作範囲を整理し、誤選択を防ぐ。Cの手前作業机、Dの接続パネルは特に確認する。
- 文字・状態・ボタンは画像に焼き込まず、ネイティブUIにする。全体縮小時も日本語を読めるサイズに保つ。重要操作のターゲットは44ptを目安にする。
- 通常・ホバー・押下・キーボードフォーカス・準備中の区別がある。色だけに依存せず名称と状態を併記する。
- 1400×900、コンパクトな1100×750前後、および横長表示で、5室の入口と4展示を操作できる。最小ウィンドウ寸法を実装と整合させる。
- マップや作品帳は閉じる操作が見える。開閉で下のシーンの位置を動かさず、背後の入口を誤クリックさせない。
- 展示閲覧中に、常時監視のCPU・メモリ負荷へ過度な負担を加えない。全室を毎フレーム同時描画せず、表示中の必要な動きだけ更新する。

## 初期レビューで留意する実装上の点

1. `CircuitLabView`の`@StateObject`と`WorkshopStore`はアプリ側の長寿命オーナーに保持し、展示を開くたびに再生成しない。
2. 保存されるルートと実際のゲーム進捗は別の状態。訪問しただけでクリアにしない。ホームの再開対象は準備中ゲームを選ばない。
3. 既存`WorkshopView`はminWidth 1100/minHeight 750。上に新しいナビゲーション帯を追加すると最小画面で盤面が押し出されるため、利用可能寸法と一体で評価する。
4. SwiftUIでは親VStackのaccessibilityIdentifierが子のボタンに継承される場合があった。IDは実操作ボタンか独立した見出しに付ける。
5. 単体UIテストには`--workshop`を明示し、展示館が初期画面になっても既存回路の回帰テストを維持する。
6. UI自動化は共有デスクトップのSpace切替でウィンドウを見失うことがある。セットアップ失敗を機能不良や合格と混同せず、失敗位置を記録する。

## テストの順序

1. テーマ・保存のモデルテスト。ルートはネイティブUIの往復でも確認する。
2. 単体アプリとモニターをwarnings-as-errorsでビルド。
3. 全20入口と準備中表示、マップ復帰、回路往復、再起動を隔離保存ファイルでUIテスト。
4. 実際のモニターで2ホーム切替、絵とクリック位置、ホイール不動、画面サイズ、音と動きを目視・操作確認。
5. 代表キャプチャと実行結果、未実装の範囲を添えて納品。

既存51モデルテストや過去の性能プロファイルは、展示館ホームが追加される前の証拠である。今回の新規動線や負荷の検証に流用しない。
